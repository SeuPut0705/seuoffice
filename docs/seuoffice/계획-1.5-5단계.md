# 1.5–5단계 실행 계획

스풋이 2026-11-08에 로드맵 남은 단계를 모두 진행하라고 했다. 이 문서는 그 일을 어떤 단위로, 어떤 순서로, 무엇으로 확인하며 하는지 적는다. 단계의 내용은 `로드맵.md`가 정본이다.

## 끝의 정의

아래가 모두 참이면 끝이다. 사람만 할 수 있는 일은 "사람 몫"에 따로 두고, 그 앞까지를 끝낸다.

1. 1.5: `@seuoffice/embed`와 `@seuoffice/web`이 `npm publish --dry-run`을 통과하고, 태그를 밀면 npm에 내는 워크플로가 있다.
2. 2: 웹에서 `mode=edit`로 연 다섯 형식(docx, xlsx, pptx, hwp/hwpx, pdf)을 고치고 저장하면 호스트의 `onSave`가 같은 형식 바이트를 받는다. 받은 바이트를 같은 엔진으로 다시 열어 고친 내용이 남아 있음을 웹 시험(Playwright)이 확인한다. `mode=view`에서는 다섯 형식 모두 고칠 수 없다(sheets 포함).
3. 2: 한글 왕복 측정 시험이 웹 저장 경로에도 돌고 불일치 0이다.
4. 3: `gateway-complete` 프로토콜로 AI 요청이 바깥 HTTP 게이트웨이를 거친다(모의 게이트웨이 시험). docs에서 AI 편집은 항상 변경 추적으로 남고, AI 도구로는 변경을 받아들이거나 거절할 수 없다.
5. 3: hwp, sheets, slides의 AI 편집이 "제안 → 미리보기 → 사람 수락"을 거친다. 앱별 조사 결과에 따라 범위를 `결정` 문서로 정한다.
6. 4: 설치본의 제품 이름, `appId`, 창 제목, 업데이트 피드가 seuoffice다. Windows 설치본 워크플로가 서명 비밀값 없이는 릴리스를 내지 않는다.
7. 5: 동시 편집 설계가 결정 문서로 있다.
8. 모든 단위가 `main`에 `--no-ff`로 합쳐지고 `CI`와 `seuoffice` 워크플로가 녹색이다.

## 단위와 순서

엄격도는 높게 둔다. 저장은 문서를 잃을 수 있는 일방향 동작이고, AI·배포 변경은 데스크톱 동작도 바꾼다. 그래서 단위마다 재현 시험이나 왕복 시험으로 끝나고, 데스크톱을 바꾸는 상위 편집은 `upstream-edits.md`에 남긴다.

| 단위 | 단계 | 내용                                                                           | 앞선 단위 |
| ---- | ---- | ------------------------------------------------------------------------------ | --------- |
| U0   | 2    | embed 저장·편집 계약: `mode=edit`, `onSave`, 더러움 알림, 호스트가 부르는 저장 | 없음      |
| U1   | 1.5  | `@seuoffice/embed`·`@seuoffice/web` npm 묶음과 게시 워크플로                   | U0        |
| U2   | 4    | 제품 이름과 업데이트 피드, 유유용 안정 판 채널, Windows 릴리스 워크플로        | 없음      |
| U3   | 3    | `gateway-complete` 프로토콜, docs AI 편집 추적 강제                            | 없음      |
| U4   | 2    | hwp/hwpx 웹 저장(+ 웹 왕복 측정)                                               | U0        |
| U5   | 2    | docx 웹 저장                                                                   | U0        |
| U6   | 2    | pptx 웹 저장                                                                   | U0        |
| U7   | 2    | xlsx 웹 저장, sheets 읽기 모드                                                 | U0        |
| U8   | 2    | pdf 웹 저장                                                                    | U0        |
| U9   | 2    | 웹 글꼴 묶음(docs·sheets 템플릿 글꼴, hwp 옛한글 글꼴)                         | 없음      |
| U10  | 2    | 암호 문서(pdf, docx) 웹 열기·저장                                              | U5, U8    |
| U11  | 3    | hwp·sheets·slides AI "제안 → 미리보기 → 수락" 조사와 구현                      | U3        |

U0는 메인 세션이 직접 만든다. 나머지는 단위마다 자기 작업 트리와 가지(`feat/*`)를 가진 세션이 맡고, 메인 세션이 검사하고 합친다. 같은 파일을 두 단위가 고치지 않도록 각 단위는 자기 앱 폴더(`apps/<앱>/src/web/` 등)만 고친다.
