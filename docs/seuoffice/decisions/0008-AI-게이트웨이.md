# 0008 AI 게이트웨이

- 날짜: 2026-11-09
- 상태: 확정

## 맥락

유유헬스케어의 AI(유비 AI)가 바깥 HTTP 게이트웨이를 거쳐 문서를 고치게 한다. 게이트웨이는 유유 쪽이 만들고 운영하므로, 그쪽이 구현할 수 있는 seuoffice 소유의 계약이 필요하다.

측정한 사실(`../웹-전환-측정.md` "AI·변경 추적·배포"):

- 제공자 층은 닫혀 있다. `packages/ai-provider/src/registry.ts`의 `AiProtocol`·`AI_PROVIDER_ADAPTERS`, `types.ts`의 `AiProviderId`, `chat.ts`의 `chatForProvider`, `stream.ts`의 `streamForProvider`가 프로토콜마다 갈라진다.
- `custom`은 OpenAI 호환(`/chat/completions`)만 받고, 키는 설정 파일 `userData/ai-settings.json`에 봉인해 둔다.
- 호출은 Electron 메인 프로세스(`docs-main.ts`의 `ai:stream`, `ai:chat`)에서 한다.

게이트웨이의 토큰은 "부른 사람"의 것이다. 요청마다 바뀔 수 있고(만료, 갱신, 사용자 전환), 설정 파일이나 로그에 남으면 안 된다.

## 결정

### 프로토콜 `gateway-complete`

OpenAI Chat Completions의 요청·스트림 모양을 그대로 쓴다. `custom` 어댑터가 이미 보내고 읽는 모양이라, 앱 쪽은 새 파서 없이 `protocols/openai-compatible.ts`의 요청 조립과 SSE 해석을 그대로 쓴다. 다른 점은 토큰을 어디서 받는지 하나뿐이다.

요청: `POST {게이트웨이 주소}/chat/completions`

- 머리글: `Content-Type: application/json`, `Authorization: Bearer <토큰>`. 토큰은 아래 "토큰"에서 요청마다 받는다.
- 본문:
  - `model`: 모델 힌트. 빈 문자열이면 게이트웨이가 고른다. 게이트웨이는 모르는 값을 거절하지 말고 자기 기본 모델로 바꿔도 된다.
  - `messages`: `system`, `user`, `assistant`(`tool_calls` 포함), `tool`(`tool_call_id`) 메시지. 그림은 `content` 배열의 `image_url`(data URL)로 온다.
  - `tools`: `{ type: "function", function: { name, description, parameters } }` 목록. 없으면 필드가 빠진다.
  - `max_tokens`, `temperature`(없을 수 있음), `stream`.
  - `stream_options: { include_usage: true }`: 받거나 무시한다. 이 필드를 이름으로 거절하는 400이 오면 앱이 이 필드 없이 한 번 다시 보내고, 그 주소에는 더 보내지 않는다.

스트림 응답(`stream: true`): `Content-Type: text/event-stream`, 줄마다 `data: <JSON>`, 끝은 `data: [DONE]`.

- 글 조각: `choices[0].delta.content`
- 도구 호출: `choices[0].delta.tool_calls[]`의 `index`, `id`, `function.name`, `function.arguments` 조각. 같은 `index`의 조각을 이어 붙인다.
- 끝: `choices[0].finish_reason`(`stop`, `tool_calls`, `length`)
- 사용량: `choices`가 빈 마지막 조각의 `usage`(`prompt_tokens`, `completion_tokens`)
- 스트림 중 오류: `data: {"error": {"message": "...", "type": "...", "code": "..."}}`

한 번에 받기(`stream: false`): 같은 요청에 `chat.completion` JSON 하나로 답한다(`choices[0].message.content`). 설정 화면의 연결 시험과 짧은 한 번짜리 호출이 쓴다.

오류:

- 2xx가 아니면 본문 `{"error": {"message", "type", "code"}}`. 앱은 상태 번호와 본문 일부를 오류 문장에 싣는다.
- 401·403: 토큰을 받지 않음. 앱은 다른 제공자로 넘어가지 않고 실패로 끝낸다.
- 429, 503, 529: 혼잡. 앱의 `aiFetch`가 두 번까지 다시 보낸다(2초, 5초. `Retry-After`가 20초를 넘으면 기다리지 않는다).
- 게이트웨이는 오류 본문에 토큰을 되풀이하지 않는다.

### 토큰

- `@genoffice/ai-provider`의 `setGatewayTokenProvider(provider)`로 프로세스가 토큰 공급자를 하나 등록한다. 공급자는 요청마다 한 번 불리고(`(signal) => string | Promise<string>`), 돌려준 값은 그 요청의 `Authorization` 머리글에만 쓰인다.
- 등록한 공급자가 없으면 기본 공급자가 요청마다 환경 변수 `SEUOFFICE_AI_GATEWAY_TOKEN`을 읽는다. 데스크톱에서는 유유 쪽 실행기나 관리자가 이 변수를 넣는다.
- 토큰이 비면 요청을 보내지 않고 `not-connected`로 멈춘다.
- 토큰은 설정이 아니다. `providers.gateway.apiKey`는 렌더러가 보낸 설정(`sanitizeAiSettings`)과 파일에서 읽은 설정(`normalizeAiSettings`) 양쪽에서 빈 값이 되고, 설정 화면에는 키 칸이 없다. 그래서 `ai-settings.json`에 토큰이 들어갈 길이 없다. 로그와 오류 문장에도 싣지 않는다.

### 설정

- 제공자 id `gateway`(이름 "AI Gateway"). 사용자나 관리자가 설정의 "고급"에서 고르고 주소(`providers.gateway.baseUrl`)를 넣는다. 모델 칸은 힌트이고 비워도 된다.
- 주소가 있으면 "설정됨"이다. `auto`는 여전히 구독만 고르므로 게이트웨이는 직접 고를 때만 쓰인다.

### 웹

웹 페이지(iframe)는 토큰을 갖지 않고 게이트웨이를 직접 부르지 않는다. 페이지는 AI 한 턴을 embed 통로로 호스트에 묻고, 호스트(유유 앱)가 자기 로그인으로 게이트웨이를 불러 스트림 사건을 페이지로 돌려준다. 요청과 사건의 모양은 위 `gateway-complete`와 같게 해서, 호스트는 받은 본문에 토큰만 붙여 넘기고 SSE를 사건으로 옮기기만 하면 된다. 이 단위에서는 embed 프로토콜을 바꾸지 않는다. 메시지 이름과 취소·오류 전달은 웹 AI 단위에서 정한다.

토큰 보관도 셋을 견줬다.

- 설정의 키 칸에 토큰 저장(`custom`처럼): 사람마다 바뀌고 만료되는 토큰이 파일에 남는다. 요구에 어긋난다.
- 설정에 "토큰 명령"을 두고 요청마다 실행(Claude Code의 `apiKeyHelper` 방식): 설정 파일의 글이 프로세스 실행으로 이어진다. 이 모듈의 규칙(설정 값을 검사 없이 spawn하지 않는다)과 부딪힌다.
- 등록한 공급자, 없으면 환경 변수(채택): 메모리에만 있고, 웹 호스트·데스크톱 실행기·시험이 같은 자리에 꽂힌다.

## 결과

- `packages/ai-provider`: `AiProtocol`에 `gateway-complete`, `AiProviderId`에 `gateway`, `AI_PROVIDER_ADAPTERS`에 어댑터(`auth: 'gateway-token'`), `protocols/gateway-complete.ts`(토큰 공급자와 두 호출), `chat.ts`·`stream.ts` 분기, `AiProviderMeta.requestToken`, 설정 검사 두 곳에서 `apiKey` 지우기, `isKeyProviderConfigured`가 주소만 보기.
- `apps/shell` 설정 화면: `requestToken` 제공자에는 키 칸을 그리지 않는다.
- 같은 단위에서 docs의 AI 편집은 늘 변경 추적으로 남고, AI 도구 목록에서 `accept_changes`·`reject_changes`가 빠진다(docs 스킬 경계). 사람은 검토 탭에서 수락·거부한다. ODT 문서는 변경 추적을 담지 못해 AI 편집이 바로 들어간다.
- 남은 일: 웹 embed 통로의 AI 메시지(웹 AI 단위), 바깥 에이전트가 열린 문서를 고치는 MCP 다리(`apps/docs/src/renderer/mcp-bridge.ts`, 추적 없이 넣고 바로 받아들인다), `ieumoffice docs apply`(에이전트 모드가 쓰는 명령줄)의 `accept_changes`·`reject_changes`와 `--track` 선택, hwp·sheets·slides의 AI 추적.
