# 0007 전부 공개

- 날짜: 2026-11-08
- 상태: 확정
- 결정한 사람: 스풋
- 대체: 0005의 "저장소는 비공개로 둔다"와 "비공개 동안 유유 배포는 읽기 토큰으로 받는다"

## 맥락

0005는 공개 여부를 1단계(웹 읽기 모드) 뒤 다시 정하기로 했다. 1단계가 끝났다. 스풋은 라이선스 사용료를 받을 생각이 없다.

## 결정

- 저장소 전체를 Apache-2.0으로 공개한다. 기업용 폴더를 따로 두는 방식(open-core)은 쓰지 않는다. GenOffice `ee/`를 들여오지 않는 규칙(경계 2)은 그대로다.
- 공개는 1단계 뒤에 한다. 공개 전에 세 가지를 마친다.
  - NOTICE에 GenOffice, 이음오피스, rhwp 출처를 정리한다.
  - 이력에 비밀값과 내부 정보가 없는지 검사한다.
  - `ee/` 반입을 막는 검사가 도는지 확인한다.
- 실제 공개 전환은 경계 3에 따라 스풋이 확인한 뒤 한다.
- (결정 0021로 바뀜: npm 대신 GitHub 릴리스의 tgz로 낸다.) 유유헬스케어는 판을 고정해 받아 쓴다. seuoffice가 판 번호를 붙여 npm `@seuoffice/*`로 내놓고, 유유는 판 올리기 커밋과 배포 전 검사를 거쳐 운영에 넣는다. PC 프로그램은 유유용 안정 판 채널을 따로 둔다.
- 공개 라이선스가 사용 권리를 주므로 유유에 따로 사용 허락 문서를 주지 않는다. 유지보수와 지원 조건은 필요하면 따로 정한다.

## 버린 대안

- 비공개 유지와 읽기 토큰: 유유 배포마다 토큰을 관리해야 하고, 사용료를 받지 않으니 비공개로 얻는 것이 없다.
- open-core(공개 핵심과 유료 기업용 폴더): 사용료를 받지 않으니 나눌 까닭이 없고, 라이선스 경계 관리만 늘어난다.
- 유유에 사용 허락 문서 주기: Apache-2.0이 이미 같은 권리를 준다.

## 결과

- 0005의 소유(스풋 개인 자산)와 반입 금지(유유 코드·설정·데이터·실문서)는 그대로다.
- 판 내기(npm `@seuoffice/*` 게시, 판 번호 규칙)와 유유용 안정 판 채널이 로드맵에 들어간다.
- 저장소가 공개되면 데스크톱 자동 업데이트는 GitHub 릴리스 피드를 쓸 수 있다.
