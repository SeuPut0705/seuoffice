# 0014 엑셀 웹 저장과 읽기 모드

- 날짜: 2026-11-09
- 상태: 확정
- 결정한 사람: U7 작업 세션(메인 세션 검토 대기)

## 맥락

엑셀(`apps/sheets`)은 브라우저에서 xlsx 엔진을 `wasm32-wasip1` 리액터로 돌려 문서를 연다. 데스크톱 저장은 주 프로세스가 맡는다. 게이트웨이(`@genoffice/xlsx-gateway`)가 바꿀 부분을 계산하고, 사이드카의 `save_archive`가 새 파일을 쓰며, 손대지 않은 부분은 압축된 바이트 그대로 옮긴다. 웹에는 주 프로세스도 Node 파일 시스템도 없다. 또 보기 모드(`?mode=view`)는 `WorkbookFile.readOnly`를 넣어도 렌더러가 읽지 않아 셀이 고쳐졌다.

## 결정

- 웹 저장은 엔진 워커 안에서 데스크톱과 같은 두 단계로 한다. 워커가 게이트웨이의 `planCellEditsToXlsx`로 바꿀 부분을 계산하고, 엔진의 `archive_manifest`, `read_entries`, `scan_entries`, `save_archive`를 부른다. 이 네 명령은 리액터(`native/xlsx-wasm`)에 이어 붙이기만 했고 엔진 크레이트는 고치지 않았다. 파일은 WASI 메모리 디렉터리(`/work`, `/save`)에 둔다. 스레드는 쓰지 않는다.
- 저장 요청을 파일의 시트 이름으로 바꾸는 부분(`writeWorkbookTo` 앞부분)을 순수 함수 `resolveWorkbookSave`(`apps/sheets/src/main/workbook-save-resolve.ts`)로 떼어 데스크톱과 웹이 함께 쓴다.
- 저장 순서는 데스크톱과 같다. 엔진이 새 파일을 쓰고, 다시 열어 읽히는지 확인한 뒤, 호스트가 바이트를 받아야(`saveToHost`) 세션을 새 파일로 바꾼다. 호스트가 거절하면 세션과 고친 내용은 그대로 남고, 렌더러는 기존 저장 실패 표시에 호스트의 까닭을 보여 준다.
- 앱의 저장 단추, Ctrl+S(웹 브리지가 데스크톱 메뉴 단축키처럼 `onMenuAction('save')`를 보낸다), 호스트의 저장 요청이 모두 같은 저장을 탄다. 호스트 요청은 데스크톱의 "닫기 전 저장" 경로(`onCloseSaveRequest`)를 쓰고, 고친 것이 없으면 지금 문서의 바이트를 그대로 넘긴다.
- 보기 모드는 세 겹으로 막는다.
  - Univer 명령: 렌더러의 기존 시트 보호 가드가 `readOnly`이면 가드가 다루는 모든 편집 명령(셀 입력, 붙여넣기, 지우기, 서식, 행·열, 정렬, 필터, 하이퍼링크)을 말없이 취소하고, 통합 문서 구조 잠금(`workbookStructureLocked`)이 참이 된다.
  - Univer 변경(mutation): 같은 가드가 열린 통합 문서에 쓰는 변경을 모두 취소한다. 가드 목록에 없는 플러그인 편집(오른쪽 단추 "노트 추가", 데이터 유효성, 그림 등)이 여기서 멈춘다. 불러오기는 `journalSuppression` 아래서 돌고, 수식 엔진의 결과는 `fromFormula`이거나 `formula.*` 변경이라 지나간다. 다른 문서 단위(수식 입력줄)의 변경도 지나간다. 이동·선택·스크롤·복사·찾기는 변경을 만들지 않는다(브라우저에서 기록해 확인).
  - 렌더러가 직접 편집 기록에 쓰는 길: 리본과 셀 오른쪽 단추 메뉴의 셸 명령(`ExcelShell`의 `dispatchCommand`, `App`의 `handleRibbonCommand`)은 보기 전용 허용 목록(`ribbonCommandAllowed`: 복사, 찾기, 이동, 메모 넘기기, 추적 화살표, 조사식 창, 통계, 화면 전환, 확대·축소, AI 패널 열기)만 실행한다. 그래서 텍스트 상자·도형·그림·차트·표 삽입과 이름 정의·링크·보호 같은 편집 대화상자가 열리지 않는다. 그림 붙여넣기·끌어 놓기도 넣지 않는다. 목록에 없는 명령은 막히는 쪽으로 둔다.
  - 데스크톱은 `readOnly`가 늘 거짓이라 동작이 같다.

## 버린 대안

- Univer 통합 문서 권한(`FWorkbook.setEditable(false)`): 렌더러가 셀 값을 불러올 때도 같은 명령(`setValues`)을 써서, 보기 모드에서 셀 내용이 아예 그려지지 않았다(브라우저에서 확인).
- 저장을 JSZip으로 브라우저에서 새로 묶기: 손대지 않은 부분이 다시 압축되어 호환성 검사(바이트 그대로 보존)를 지킬 수 없다.
- 엔진에 바이트를 주고받는 새 저장 명령 만들기: 엔진 크레이트를 고쳐야 하고, 기존 `save_archive`와 사후 목록 검사(`assertManifestPreserved`)를 두 벌로 둔다.

## 결과

- 웹 저장 결과에서 손대지 않은 부분은 압축 바이트, CRC, 시간까지 원본과 같다(`apps/web/tests/save-xlsx.spec.ts`).
- 큰 시트를 바꿔 쓰는 스트리밍 패치(`stream_patches`)는 웹에 없다. 게이트웨이도 데스크톱 저장에서 이를 쓰지 않는다.
- 보기 모드에서 막는 곳은 Univer 명령 가드, Univer 변경 가드, 셸 명령(리본·오른쪽 단추 메뉴), 그림 붙여넣기·끌어 놓기다. AI 패널은 웹에 공급자 브리지가 없어 편집을 만들지 못한다. Univer를 거치지 않고 편집 기록에 바로 쓰는 새 길을 상위가 셸 명령 밖에 더하면 거기도 막아야 한다.
