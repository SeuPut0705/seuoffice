# 0018 웹 슬라이드 AI는 제안으로

- 날짜: 2026-11-09
- 상태: 확정
- 결정한 사람: U14 작업 세션(메인 세션이 맡김). 스풋이 뒤집을 수 있다.

## 맥락

결정 0012는 slides의 AI 한 번의 실행을 제안으로 붙잡는다. 실행이 도는 동안 덱을 잠그고, 끝나면 실행 전으로 되돌려 제안으로 들고, 사람이 받아들여야 넣는다. 이 일은 데스크톱 메인 프로세스가 한다(`apps/slides/src/main/ai-proposal.ts`, `session-state.ts`의 기록 묶음, `slides-main.ts`의 IPC).

결정 0017로 웹 AI가 호스트를 거쳐 게이트웨이를 부르게 되었다. 그런데 slides 웹 브리지는 AI 패널이 실행 전에 부르는 `beginHistoryBatch`·`aiRunBegin`을 `WebUnsupportedError`로 거절했다. 켜 두면 모든 요청이 실패하므로 결정 0017은 slides를 "연결 안 됨"으로 두었다.

웹 slides는 이미 페이지 안에 데스크톱과 같은 모양의 세션(`Session`)을 두고, 데스크톱의 편집 코드를 그대로 불러 쓴다(`apps/slides/src/web/session.ts`, `deck-edits.ts`).

## 결정

1. 편집 모드(`?mode=edit`)의 웹 브리지가 AI 실행 경로를 페이지의 세션 위에서 돌린다. 데스크톱 코드를 그대로 부른다.
   - `beginHistoryBatch`·`endHistoryBatch`: `session-state.ts`의 같은 이름 함수와 `registerAiSnapshot`.
   - `aiRunBegin`·`aiRunHold`·`aiProposalAccept`·`aiProposalReject`: `ai-proposal.ts`의 `beginAiRun`·`holdAiRun`·`acceptAiProposal`·`rejectAiProposal`. 페이지에는 창이 하나뿐이라 주인 번호는 1로 고정한다.
   - `aiSnapshotRestore`: `restoreAiSnapshot`.
   - `applyTxn`(AI의 `apply_ops` 도구): `slides-main.ts`의 `applySessionTxn` 본문을 새 파일 `main/session-txn.ts`의 `applyTxnToSession`으로 옮기고, 기록을 남기는 세 동작(실행 전 기록, 되물리기, 실행)을 받게 했다. 데스크톱은 지금처럼 `pushHistory`와 기록장(`journaledTxn`)을 넘기고, 페이지는 자기 판 번호를 세는 기록을 넘긴다.
2. 실행 동안의 잠금은 데스크톱과 같다.
   - 저장(앱의 저장, 호스트의 `request_save`)은 `reason: 'ai-review'`로 거절한다. 호스트의 `doc.save()`는 `save_failed`가 된다.
   - 실행 취소·다시 실행을 거절한다.
   - 기록 알림의 `aiRunActive`가 참이 되어 렌더러가 AI 창 밖의 입력을 막는다.
   - 실행 전에 시작한 저장이 아직 호스트에 쓰는 중이면 실행은 그 저장이 끝난 뒤 시작한다. 저장은 `trackWrite`로 세고, 시작 전에는 데스크톱의 `settleWrites`로 기다린다. 이 기다림은 데스크톱처럼 30초까지만이다. 호스트의 `onSave`가 끝나지 않으면 그 실행은 시작하지 않고 거절되므로(패널은 "AI가 편집하는 동안 덱은 읽기 전용" 문구를 보인다), 기다리는 동안 대화를 리셋해도 패널이 그 뒤로 막혀 있지 않는다.
3. 실행이 끝나면(끝남, 멈춤, 오류, 새 대화) 렌더러가 늘 하던 대로 `aiRunHold`를 부르고, 덱은 실행 전으로 돌아가 제안 카드가 나온다. 제안을 들고 있는 동안의 저장은 실행 전 덱을 쓴다. 받아들이기는 실행 결과 전체를 한 번에 넣고, 거부하면 덱은 실행 전 그대로다.
4. 페이지의 "저장됨" 판단(판 번호)이 데스크톱 함수가 찍은 기록과 어긋나지 않게, 그 함수들이 만든 기록마다 판 번호를 붙인다. 되돌리면 실행 전 판으로, 받아들이면 실행 결과의 판으로 돌아가므로, 받아들인 덱은 저장 안 됨으로 보인다.
5. 보기 모드에서는 실행을 붙잡지 않는다. `beginHistoryBatch`가 거짓을 돌려주어 AI는 답하고, 덱을 고치는 도구(`applyTxn` 등)는 `WebUnsupportedError('slides.edit')`로 거절되어 그 오류가 모델에게 간다.
6. slides 웹의 `getAiSettings`는 다른 앱처럼 `webAiSettings()`다. 호스트가 AI를 주면 "AI Gateway"가 연결된 것으로 보인다.
7. `setImmediate`가 없는 브라우저를 위해 웹 층 전역에 `setTimeout(0)`으로 둔다. 데스크톱 세션 코드가 기록 알림을 이것으로 미룬다. 페이지에는 붙은 창 목록(`sessions`)이 비어 있어 그 알림은 아무 창에도 보내지 않는다. 페이지의 알림은 `deck-edits.ts`가 한다.

## 결과

- 웹 slides 편집 모드에서 AI의 `apply_ops` 편집이 제안으로 붙잡힌다.
  - 실행 중 호스트 저장은 거절된다.
  - 제안을 든 동안 저장하면 실행 전 덱이 저장된다.
  - 받아들인 뒤 저장하면 AI 편집이 들어간다.
  - 다음 실행을 거부하면 덱과 저장이 그대로다.
  - 웹 시험 `apps/web/tests/ai-relay.spec.ts`가 엔진으로 저장 바이트를 다시 열어 확인한다. 보기 모드 시험도 있다.
- 웹에서 되는 AI 편집 도구는 `apply_ops` 하나다. `execute_slide_script`(`applyEditScript`), 차트·그림·페이지 생성 도구는 웹 브리지가 여전히 거절하므로 모델은 오류를 받고 `apply_ops`로 다시 해야 한다. 웹 차이 목록에 남는다.
- hwp 웹 AI(결정 0017에서 연결)도 같은 웹 시험으로 확인했다. AI 편집은 제안으로 붙잡히고, 제안 동안 저장은 실행 전 문서를, 받아들인 뒤 저장은 AI 편집을 담는다.
- 상위 파일 고침: `apps/slides/src/main/slides-main.ts`(본문을 `session-txn.ts`로 옮김), 새 파일 `apps/slides/src/main/session-txn.ts`, `apps/slides/src/main/ai-proposal.ts`(`settleWrites`를 내보냄).
