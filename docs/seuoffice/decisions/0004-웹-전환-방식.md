# 0004 웹 전환 방식

- 날짜: 2026-11-08
- 상태: 확정

## 맥락
렌더러는 `electron`이나 `node:*`를 직접 import하지 않고, 각 앱 preload의 `contextBridge` 객체(`window.desktop`, `pdfApi`, `hwpApi`, `slidesApi`, `desktopApi`)로만 메인 프로세스와 통신한다. 문서 해석은 앱마다 다른 곳에 있다(pdf·docx는 렌더러, pptx는 메인 TS, xlsx는 메인의 Rust 사이드카, hwp는 스튜디오 iframe).

## 결정
- 렌더러는 고치지 않는다. 앱마다 `window.<bridge>`의 웹 구현을 부팅 전에 설치한다(`createWebBridge`, `installWebBridge`).
- 열기에 필요한 메인 쪽 순수 로직은 상위 모듈을 그대로 import해 브라우저 메인 스레드에서 돌린다.
- Node 내장 모듈과 `electron`은 Vite 별칭으로 브라우저 shim(`@seuoffice/web-platform`)에 연결한다. shim은 import는 안전하고 호출할 때만 던진다.
- xlsx는 Rust 엔진을 `wasm32-wasip1` reactor로 빌드해 Worker에서 돌린다. 엔진 편집은 `#[cfg(target_os = "wasi")]` 분기로만 한다.
- 문서는 `@seuoffice/embed`가 iframe에 postMessage로 넘긴다.

## 버린 대안
- Electron 메인 프로세스 통째 에뮬레이션: 셸과 888개 IPC 핸들러를 끌고 온다.
- 렌더러 재작성: 상위를 따라갈 수 없고 일이 앱마다 수만 줄이다.

## 결과
- 새 코드는 `packages/web-platform`, `packages/embed`, `apps/web`, `apps/<app>/vite.web.config.ts`, `apps/<app>/src/web/`, `apps/sheets/native/xlsx-wasm/`에 둔다.
- 기본값이나 거절로 처리한 브리지 메서드는 `../web-gaps.md`에 모은다.
