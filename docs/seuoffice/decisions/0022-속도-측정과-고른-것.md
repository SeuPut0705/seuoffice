## 결정

- **CI를 나눠 동시에 돌린다.** `test` 작업은 4몫(`tools/seuoffice-test-shard.mjs`, 잰 초로 균형), `e2e` 작업은 Playwright shard 6개. 작업 공간이 정확히 한 몫에만 들어가는지 도구가 돌기 전에 검사한다. lint와 typecheck는 첫 몫에서만 돈다.
- **글꼴 패키지를 캐시한다.** 시각 기준용 `.deb` 세 개를 캐시에 두고 `dpkg`로 깐다.
- **설치본에서 안 쓰는 것을 뺀다.** `modules/*/main`을 넣지 않는다(`apps/shell/electron-builder.seuoffice.cjs`). 릴리스 워크플로가 설치본에 `modules/*/main`이 없는지 검사한다.
- **웹은 압축해서 보내라고 문서에 적는다.** `apps/web/README.md`에 형식별 바이트와 서버 설정에 넣을 MIME 형식을 적었다.

## 버린 대안

- **메인 번들 컴파일 캐시**(홈 668 → 570ms, 측정함). 시작 파일을 하나 더 두고 `userData` 경로를 번들보다 먼저 알아야 한다. 홈이 이미 0.7초라 얻는 0.1초에 비해 건드리는 곳이 많다.
- **데스크톱 JS minify**(설치 뒤 −55MB, 평가 −38ms). 함수·클래스 이름에 기대는 코드가 깨질 수 있고 오류 기록의 스택을 읽기 어려워진다.
- **rhwp wasm을 한 벌만 싣기**(zip −9.6MB), **pptx 글꼴 색인을 메인 스레드 밖으로**(pptx −100ms), **MCP 초기화를 창 뒤로**(−30ms). 모두 상위 파일을 고쳐야 하고 이득이 작다. 이음이 고치면 따라 받는다.
- **Electron 로케일을 21개 언어 것만 싣기**(Mac zip −7.3MB, Windows 설치 파일 −5.0MB). v0.12.20에 넣었다가 v0.12.21에서 되돌렸다. 시스템 언어의 로케일 파일이 없으면 Chromium이 `en-US`로 돌고, 로케일을 주지 않고 만드는 날짜·숫자가 미국식이 된다. 스웨덴어 시스템으로 재니 `2026-11-09`가 `11/9/2026`이 됐다. 시트 인쇄 머리글, 슬라이드 날짜 넣기, PDF 서명 날짜가 여기에 걸린다. 푸시 뒤에 받은 독립 검토가 찾았다.
- **웹 묶음에 미리 압축한 `.br` 파일을 넣기.** 호스트가 그 파일을 골라 보내도록 설정해야 효과가 있는데, 그 설정을 할 수 있으면 서버 압축을 켜는 것으로 충분하다. 묶음만 커진다.
- **Mac 빌드를 둘로 나누거나 두 채널 묶기를 동시에.** 지금 릴리스 시간을 정하는 것이지만, 같은 폴더에서 electron-builder 둘을 함께 돌리는 것이 안전한지 확인하지 못했다. 다음에 볼 후보다.

## 결과

- 푸시에서 판까지 걸리는 시간은 CI가 아니라 Mac 빌드와 macOS 러너 대기가 정한다.
- 실제 릴리스 파일(v0.12.17 → v0.12.21): Mac 업데이트 zip 281.1 → 265.2MB(−15.9MB, −5.6%), Mac dmg 278.2 → 262.4MB, Windows 설치 파일 231.3 → 218.6MB(−12.7MB, −5.5%). Windows 빌드는 `modules/*/main`이 없는지 보는 검사와 창 없는 내보내기 시험을 통과했다.
- 첫 실행 안내는 기본 앱 상태를 읽은 뒤에 뜬다(최대 1.5초 기다림). Mac에서 그 읽기는 50ms였다(7번, 첫 번째만 88ms). Windows는 재지 못했다.
- 알게 된 결함: 데스크톱 한글 편집기가 옛한글 글꼴 `RHWPOldHangul-Regular.woff2`를 찾지 못한다(404). 웹 빌드는 이 글꼴을 복사하는데 데스크톱은 하지 않는다. 이번에 고치지 않았다.
