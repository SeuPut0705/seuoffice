# 0016 한글 웹 보기 모드는 읽기 전용 편집기

- 날짜: 2026-11-09
- 상태: 확정
- 결정한 사람: U4b 작업 세션(메인 세션이 맡김). 스풋이 뒤집을 수 있다.

## 맥락

웹에서 `?mode=view`로 연 한글 문서(hwp, hwpx)를 고칠 수 있었다. 웹 브리지(`apps/hwp/src/web/bridge.ts`)는 저장만 막았고, 편집 화면인 rhwp studio(iframe)는 그대로 편집기였다. 글을 치면 문서가 바뀌고 "저장 안 됨" 상태가 되었다.

rhwp에는 읽기 전용 모드가 없다.

- `@rhwp/editor`의 `createEditor` 옵션은 studio 주소, chrome(메뉴·도구 막대·상태 표시줄 숨기기)뿐이다. 숨겨도 명령은 실행된다.
- studio의 양식 모드(`view:form-mode`)는 가장 가깝지만, 양식 필드·양식 개체(확인란 등) 편집, 그림·도형 끌기, 표 테두리 끌기, 되돌리기·찾아 바꾸기, 플러그인 명령(`ext:*`)이 그대로 지나간다. 사용자가 메뉴에서 끌 수도 있다.
- 배포용 문서도 읽기 전용으로 열지 않는다. studio가 열 때 `convertToEditable()`로 편집 가능 문서로 바꾼다.

## 결정

1. 웹 브리지는 편집 모드(`?mode=edit`)가 아니면 한글 앱 페이지의 뿌리 요소에 `data-studio-read-only`를 단다. 렌더러가 studio iframe을 만들기 전이다. 보기 모드와 모드 없음이 같다(엑셀 웹 브리지의 `readOnly: !editMode()`와 같다).
2. studio는 시작할 때 한 번 부모 페이지의 그 속성을 읽는다(`studio-plugin/read-only.mjs`, `STUDIO_READ_ONLY`). 다른 출처의 부모, 최상위 창, 속성이 없는 부모는 읽기 전용이 아니다. 데스크톱은 속성을 달지 않으므로 동작이 같다.
3. 읽기 전용 studio는 세 겹으로 막는다. 빌드 패치 셋(`studio-read-only-commands`, `-operations`, `-document`)이 걸고, 속성이 없으면 셋 다 아무것도 하지 않는다.
   - 명령: studio 디스패처의 양식 모드 차단 자리에서, 읽는 명령만 남긴다. 복사, 모두 선택, 찾기, 다시 찾기, 쪽 이동, 인쇄, PDF로 인쇄, 정보, 환경 설정, `view:*`(양식 모드 전환 제외), 앱 플러그인 명령(`ext:*`)이다. 나머지(되돌리기, 다시 실행, 오려 두기, 붙이기, 지우기, 찾아 바꾸기, 모양 붙이기, `format:*`, `insert:*`, `table:*`, `page:*` 등)는 메뉴·도구 막대·오른쪽 단추 메뉴에서 꺼지고 단축키도 듣지 않는다. 목록에 없는 명령은 막히는 쪽이다.
   - 편집 연산: 입력 처리기의 `isOperationAllowedInEditMode`가 모든 연산을 거절한다. 글 입력, 지우기, 문단 나누기, 붙이기, 플러그인 변경 묶음(`host.transaction`, AI·메모·문서 점검의 고치기)이 문서에 닿기 전에 말없이 멈춘다. 플러그인 쪽은 이미 있는 "편집 모드에서 거절" 오류를 받는다.
   - 엔진 문서: studio가 문서를 넘겨받는 자리(`loadDocumentAtomically`)에서 엔진 `HwpDocument`를 프록시로 감싼다. 읽기, 그리기, 내보내기, 맞히기 검사, 캐럿 이동, 편집기 안 클립보드, 되돌리기용 캡처, 글꼴, 조판, 표시 설정 호출만 지나가고, 나머지 호출은 모두 예외를 던진다. 앞의 두 겹이 놓친 길(그림·표 테두리 끌기, 양식 개체 누르기, IME 조합 입력)도 문서를 바꾸지 못한다. 읽는 호출은 이름 규칙(허용 목록)으로 정하므로, 나중 엔진이 더한 모르는 호출은 변경으로 본다.
4. 앱 플러그인 명령(`ext:*`)은 메뉴에서 켜진 채로 둔다. 읽는 명령(글자 수, 표시, 앱 파일 메뉴)이 돌아야 하고, 편집하는 것은 뒤의 두 겹에서 멈춘다.

## 버린 대안

- 양식 모드 강제: 위의 구멍(양식 필드·개체, 끌기, 되돌리기, 플러그인 명령)이 남는다.
- 편집기 위에 투명한 막: 스크롤·찾기·복사까지 막힌다. 키보드 초점이 iframe 안으로 들어가면 막이 소용없다.
- 웹 층에서 studio iframe의 키·붙이기·마우스 이벤트를 가로채기(`save-key.ts` 방식): 명령 상태가 메뉴에 드러나지 않고, 끌기와 양식 개체처럼 이벤트로 가를 수 없는 편집이 남는다. studio가 새 입력 길을 더하면 조용히 샌다.
- studio 주소에 `readonly=1` 붙이기: 렌더러(`studio-settings.ts`의 `studioUrl`, `App.tsx`)와 IPC 계약을 고쳐야 한다. 부모 속성은 웹 층만 고친다.
- 엔진 호출을 막는 목록(차단 목록)으로 정하기: 나중 엔진의 새 변경 호출이 그대로 지나간다.

## 결과

- 웹 보기 모드(와 모드 없음)에서 한글 문서는 고쳐지지 않고 "저장 안 됨" 상태도 되지 않는다. 화면 보기, 스크롤, 확대·축소, 찾기, 선택, 복사는 된다.
- 막힌 엔진 호출은 studio 콘솔에 오류를 남긴다(문서는 그대로다).
- 편집 모드와 데스크톱은 그대로다. 패치는 데스크톱 studio 빌드에도 들어가지만 속성이 없으면 거짓인 상수 하나를 볼 뿐이다.
- rhwp를 올릴 때 패치 자리가 사라지면 빌드가 실패한다(기존 패치 규칙). 엔진 허용 목록은 `apps/hwp/tests/read-only.test.ts`가 변경 호출 거절, 읽기 호출 통과, 모르는 호출 거절을 확인한다.
