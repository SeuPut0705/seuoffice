# 0012 AI 편집 검토

- 날짜: 2026-11-09
- 상태: 확정

## 맥락

스풋의 규칙: AI가 고친 것은 사람이 받아들이기 전에는 문서에 들어가지 않는다. docs는 결정 0009에서 모든 AI 편집을 작성자 `AI Assistant`의 변경 추적으로 남기고, AI는 받아들이기·거부를 하지 못하게 했다. hwp, sheets, slides는 각자 AI 도우미가 있고 지금은 고친 것을 바로 문서에 넣는다.

측정한 사실(이 단위에서 코드를 읽어 확인했다):

| 항목                       | hwp                                                                                                                                                            | sheets                                                                                                                               | slides                                                                                                                                                                                        |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 결정

세 앱 모두 docs처럼 형식 안의 변경 추적을 쓸 수 없다. 그래서 앱 안에서 "AI 한 번의 실행"을 제안으로 붙잡는다.

1. 실행 중에는 지금처럼 AI가 문서를 바로 고친다. AI의 다음 도구 호출이 자기가 고친 결과를 읽어야 하기 때문이다.
2. 실행이 도는 동안 문서는 그 실행의 것이다. 사람은 문서를 고칠 수 없고(입력은 창의 캡처 단계에서 막고, 앱의 편집 관문도 거절한다. AI 창은 그대로 쓴다), 어떤 저장 길(저장, 다른 이름으로 저장, 자동 저장, 복구 사본, 닫을 때 저장, 내보내기)도 쓰지 않는다. 다른 파일을 여는 것도 거절한다. 실행 전에 시작한 저장이 아직 쓰는 중이면 실행은 그 저장을 기다린 뒤 시작한다. 그래서 실행 끝의 되돌리기는 AI 편집만 덜어 내고, 받아들이지 않은 편집이 파일에 쓰이지 않는다.
3. 실행이 끝나면(끝남, 멈춤, 오류, 횟수 한도, 새 대화로 끊김 모두) 문서를 고친 실행은 그 앱이 이미 가진 되돌리기 장치로 실행 전 상태로 되돌린다. 되돌린 것은 제안으로 들고 있는다. 답 아래 카드에 미리보기와 "받아들이기"·"거부" 단추가 나온다.
4. 되돌릴 수 없게 될 편집은 처음부터 하지 않는다. 앱의 실행 취소에 다 담기지 않을 크기의 편집은 적용 전에 도구 오류로 거절하고, 모델에게 작게 나눠 다시 하라고 알린다. 그래도 되돌리기가 실패하면 문서를 그대로 잠그고 저장을 계속 거절한다. 그 문서는 저장하지 않고 닫아야 한다.
5. 받아들이기는 제안 그대로를 다시 넣는다. 그동안에도 2의 잠금이 걸린다. 되돌린 뒤 문서가 바뀌었으면 넣지 않고 제안이 낡았다고 알린다. 받아들인 뒤에는 앱의 원래 "이 답 되돌리기"와 실행 취소가 지금처럼 동작한다.
6. 거부하면 제안을 버린다. 문서는 실행 전 그대로다.
7. 제안이 남아 있는 동안에는 새 AI 요청을 보내지 못한다.

앱별로 쓰는 장치:

- hwp: 실행 동안 플러그인이 편집기의 편집 관문(`isOperationAllowedInEditMode`, `scripts/rhwp-patches.mjs`의 `studio-ai-run-lock` 패치)과 편집기 창의 입력을 잠그고, 플러그인 자신의 변경만 통과시킨다. 메모 창의 사람 편집도 거절한다. 실행 끝에 플러그인 `undo(바뀐 곳 수, 실행 시작 때 foreign)`로 되돌린다. 받아들이기는 새 플러그인 메서드 `redo(단계 수, 되돌린 뒤 foreign)`가 편집기의 `edit:redo`로 다시 넣으며, 모자라게 돌아오면 같은 호출 안에서 다시 덜어 내 일부만 들어가는 일이 없다. 한 실행의 변경 수는 편집기 기록 용량 안으로 제한한다(넘으면 `RUN_TOO_LARGE`). 미리보기는 기존 바뀐 곳 목록이다. 거부하거나 낡으면 다음 요청에 "사용자가 되돌렸다"는 기존 안내(`REVERTED_NOTE`)가 붙는다.
- sheets: 실행 동안 사람의 입력을 창 캡처 단계에서 막고(AI 창 제외), Univer `BeforeCommandExecute`에서 사람의 변경 명령을 거절한다. 실행이 적용한 `ChangePlan`을 순서대로 적어 두고, 실행 끝에 기존 [실행 취소]와 같은 길로 되돌린다(열린 파일은 Univer 실행 취소, 빈 통합 문서는 어댑터 이력). 미리보기는 기존 "제안된 변경" 카드(주소, 전 → 후, 서식·시트 이름·구조 변경)다. 받아들이기는 적어 둔 계획을 기존 적용 길(`autoApplySafePlan`)로 다시 넣는다. 낡음은 열린 파일에서 Univer 실행 취소 더미의 새 항목과 `planStillMatches`로, 빈 통합 문서에서 어댑터 리비전으로 본다. 뒤 계획이 거절되면 앞 계획을 되돌린다. 실행 취소에 남지 않을 계획(10만 셀 넘음, Univer 실행 취소 더미 20칸을 넘김, 저널에만 남는 `protect_sheet`·`set_page_setup`·`add_sparkline`·`delete_table`)은 적용 전에 거절한다. AI 도구 `merge_attached_workbooks`(첨부 통합 문서를 열린 문서에 들여오기)는 실행 취소 단계 없이 문서에 들어가므로 AI에게 내주지 않는다. 사람의 데이터 ▸ 통합 문서 병합은 그대로다.
- slides: 실행을 시작할 때 메인 프로세스가 덱과 실행 취소·다시 실행 더미를 기록한다(`src/main/ai-proposal.ts`). 실행 동안 메인이 모든 창에 잠금을 알리고, 렌더러가 AI 창 밖의 입력과 메뉴 편집 명령을 막으며, 메인은 실행 취소·다시 실행과 모든 직렬화(`writeDeckFile`, 복구 사본, MCP 저장, 템플릿 바이트)를 거절한다. 실행이 끝나면 실행 뒤 상태를 떠 두고 덱과 두 더미를 실행 전 모양으로 되돌린다. 받아들이기는 실행 취소 한 단계를 쌓고 실행 뒤 상태를 넣으며, 실행 전 상태를 기존 AI 되돌리기 지점으로 등록한다. 낡음은 실행 취소 더미 맨 위·길이, 다시 실행 길이, 편집 순번으로 본다. 미리보기는 달라진 슬라이드(최대 4장)의 전·후 축소 그림이다. `generate_deck`의 교체 모드는 파일에서 연 덱이면 거절한다. 교체는 경로가 없는 새 세션을 만들어 스냅샷으로 되돌릴 수 없기 때문이다. 모델에게는 새 페이지를 덧붙이고 옛 페이지를 지우라고 답한다(그것은 제안으로 붙잡힌다). 경로가 없는 새 덱의 교체는 붙잡힌다. 다른 창이 같은 덱으로 실행 중이거나 마스터 보기이면 실행을 시작하지 않는다.

## 결과

- 세 앱의 AI 편집은 실행이 끝나면 문서 밖의 제안이 되고, 사람이 받아들여야 문서에 들어간다. 각 앱에 가짜 모델로 진짜 `AgentLoop`와 앱의 스킬을 돌려 (가) 받아들이기 전 문서가 실행 전과 같고, (나) 받아들이면 실행이 만든 상태와 같고, (다) 거부하면 실행 전과 같고, (라) 되돌린 뒤 문서가 바뀌면 받아들이기가 거절되고 문서가 그대로인 것을 보는 시험이 있다(`apps/hwp/tests/ai-turn-proposal.test.ts`, `apps/sheets/tests/ai-turn-proposal.test.ts`, `apps/slides/tests/ai-proposal.test.ts`·`ai-panel-proposal.test.ts`). hwp는 진짜 rhwp 문서를 `exportHwp()` 바이트로, slides는 진짜 세션의 슬라이드와 압축 항목 바이트로, sheets는 빈 통합 문서 어댑터의 전체 상태로 견준다.
- 잠금 시험(`apps/hwp/tests/ai-run-lock.test.ts`, `apps/sheets/tests/ai-run-lock.test.ts`, `apps/slides/tests/ai-run-fail-closed.test.ts`): 실행 중 저장·자동 저장·복구 사본이 거절되고 실행 뒤 저장은 실행 전 문서를 쓴다. 실행 중 사람의 입력(키, 붙여넣기, 누르기)이 문서에 닿지 않고, 거부 뒤 문서는 실행 전과 같으며 실행 전에 한 사람의 편집은 남는다. sheets는 AI 적용이 비동기로 멈춘 사이와 받아들이기 도중의 입력·저장도 막히는 것을 본다. slides는 실행 전에 시작해 멈춰 있던 저장이 실행 전 덱을 쓰는 것을 본다.
- 진짜 rhwp 편집기(웹에서 띄운 스튜디오)에서 플러그인으로 문단을 넣고 `undo`·`redo`를 부르면 내보낸 바이트가 실행 전·후와 같았다.
- 사람이 받아들이거나 거부해야 다음 AI 요청을 보낼 수 있다. "새 대화"나 다른 문서 열기는 제안을 버린다(실행 중이면 열기는 거절된다).
- 실행이 중간에 버려져도(새 대화, 프로젝트 대화로 옮김, 창 닫힘·새로 고침) 그 실행은 되돌려 버리고 잠금을 푼다. 실행마다 세대를 두어, 버려진 실행의 늦은 잠금 풀기가 다음 실행의 잠금을 풀지 못하고, 버려진 실행의 되돌리기가 끝나기 전에는 다음 실행이 시작되지 않는다. hwp와 slides에서 보낸 직후(준비 중)의 새 대화나 창 닫힘은 모델 요청 전에 그 실행을 끝낸다. slides에서 같은 덱을 연 두 창 중 실행한 창이 사라지면 그 실행을 되돌리고 남은 창의 잠금을 푼다. 실행 시작이 저장을 기다리는 사이 그 창이 사라졌으면 실행을 시작하지 않는다.
- hwp의 인쇄·PDF 내보내기(`print-flow.ts`의 `runPrintJob`, 실행 잠금 확인이 필수 인자)는 페이지를 모으는 도중 실행이 시작되면 그 작업을 그만둔다. 실행 중인 편집이 인쇄물에 들어가지 않는다. 시험은 진짜 AI 창의 보내기로 잠금을 걸고, 메인 프로세스로 아무것도 넘어가지 않는 것을 본다.
- 실행이 끝난 뒤(멈춤, 새 대화, 패널 사라짐) 늦게 도착한 AI 쓰기는 문서에 들어가지 않는다. slides는 그림 넣기·바꾸기, 생성 페이지 넣기(덧붙이기·바꾸기·끼우기·교체), 차트 고치기, 미디어 넣기가 기다린 뒤 실행이 바뀌었으면 기록도 변경도 하지 않는다. hwp는 도구 호출마다 자기 실행의 중단 신호를 묶어, 끝난 실행의 도구는 다음 실행 중에도 편집기를 부르지 못하고 바뀐 곳도 기록하지 못한다. 되돌릴 단계 수는 패널이 센 수가 아니라 플러그인이 잠금 아래에서 직접 센 수(`runSteps`)로 정해, 가는 중이던 쓰기도 되돌리거나 제안에 넣는다.
- sheets는 제안이 남아 있는 동안 저장·다른 이름으로 저장을 거절하고 "먼저 받아들이거나 거부하라"고 알린다. 저장 뒤 같은 파일을 다시 여는 과정이 제안을 버리기 때문이다. 복구 사본과 템플릿 내보내기는 다시 열지 않아 그대로 된다.
- sheets 빈 통합 문서에서 실행을 되돌릴 때 실행 전에 떠 둔 격자로 복원해, 사람이 격자에만 친 셀이 사라지지 않는다. 받아들이기가 중간에 실패해 되감을 때는 받아들이기 직전에 떠 둔 격자로 돌아가, 제안이 걸린 동안 사람이 친 셀도 남는다.
- 다시 실행으로 붙잡힌 실행을 되살릴 수 없다. sheets는 AI 단계를 되돌린 바로 뒤(붙잡을 때, 받아들이기가 거절되어 롤백할 때)에만 Univer 다시 실행 더미를 비운다. 아무것도 고치지 않은 AI 요청은 사람의 다시 실행 기록을 건드리지 않는다. hwp는 붙잡은 실행이 다시 실행 더미에 있는 동안 플러그인 밖의 다시 실행을 거절하고, slides는 다시 실행 더미를 실행 전 모양으로 되돌린다.
- 남은 위험: sheets에서 Univer 명령을 거치지 않고 저널에만 쓰는 대화상자 편집(페이지 설정, 스파크라인 등)은 명령 거절에 걸리지 않는다. 그 대화상자를 여는 입력은 창 잠금이 막는다.
- 남은 위험: 잠금 중에는 편집기 도구 모음도 눌리지 않는다(스크롤만 된다). 실행을 멈추려면 AI 창의 멈춤 단추를 쓴다.
- 남은 일: hwp에서 거부한 뒤 사람이 자기 편집을 Ctrl+Z로 되돌리면, 다음 받아들이기·거부·새 실행 전까지 Ctrl+Shift+Z가 막힌다. 편집기가 다시 실행 목록의 깊이를 알려 주지 않아 사람의 되돌리기와 거부한 AI 단계를 가를 수 없고, 막음을 풀면 거부한 실행이 되살아난다. 편집기에 다시 실행 깊이를 읽는 길이 생기면 고친다.
- 남은 일: sheets와 slides는 거부를 모델에게 알리는 안내가 없다. 다음 요청의 문맥이 지금 문서를 다시 읽어 주지만, 대화 기록에는 적용했다는 도구 결과가 남는다. 세 앱 모두 Electron 화면에서 카드를 눈으로 확인하지 못했다(패널은 jsdom 시험으로 본다. sheets는 진짜 `App`을 jsdom에 띄워 새 대화·제안 중 저장·빈 통합 문서 되돌리기를 본다).
- 남은 일: sheets 빈 통합 문서에서 구조 변경 계획을 적용하거나 받아들일 때, 그리고 사람이 이미 받아들인 AI 답을 되돌릴 때는 격자를 어댑터에서 다시 만들어 격자에만 있던 입력이 사라질 수 있다. 어댑터와 격자가 각자 원본이라 한쪽으로 합쳐야 하고, 이번에는 거부의 복원만 정확히 했다. 제안 중 저장 거절은 빈 통합 문서로 시험했고 파일을 다시 여는 경로는 시험하지 못했다.
- 범위 밖: 새 문서를 만드는 AI 경로(sheets `create_document`, slides 프로젝트 "만들기"로 넘어온 덱)는 열린 문서를 고치지 않아 그대로 둔다. 웹 빌드의 AI는 여전히 지원하지 않는다(웹 AI 단위).
