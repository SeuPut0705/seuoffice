# 0012 AI 편집 검토

- 날짜: 2026-11-09
- 상태: 확정

## 맥락

스풋의 규칙: AI가 고친 것은 사람이 받아들이기 전에는 문서에 들어가지 않는다. docs는 결정 0009에서 모든 AI 편집을 작성자 `AI Assistant`의 변경 추적으로 남기고, AI는 받아들이기·거부를 하지 못하게 했다. hwp, sheets, slides는 각자 AI 도우미가 있고 지금은 고친 것을 바로 문서에 넣는다.

측정한 사실(이 단위에서 코드를 읽어 확인했다):

| 항목                       | hwp                                                                                                                                                            | sheets                                                                                                                               | slides                                                                                                                                                                                        |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 결정

세 앱 모두 docs처럼 형식 안의 변경 추적을 쓸 수 없다. 그래서 앱 안에서 "AI 한 번의 실행"을 제안으로 붙잡는다.

1. 실행 중에는 지금처럼 AI가 문서를 바로 고친다. AI의 다음 도구 호출이 자기가 고친 결과를 읽어야 하기 때문이다.
2. 실행이 끝나면(끝남, 멈춤, 오류, 횟수 한도 모두) 문서를 고친 실행은 그 앱이 이미 가진 되돌리기 장치로 실행 전 상태로 되돌린다. 되돌린 것은 제안으로 들고 있는다. 답 아래 카드에 미리보기와 "받아들이기"·"거부" 단추가 나온다.
3. 받아들이기는 제안 그대로를 다시 넣는다. 되돌린 뒤 문서가 바뀌었으면 넣지 않고 제안이 낡았다고 알린다. 받아들인 뒤에는 앱의 원래 "이 답 되돌리기"와 실행 취소가 지금처럼 동작한다.
4. 거부하면 제안을 버린다. 문서는 실행 전 그대로다.
5. 제안이 남아 있는 동안에는 새 AI 요청을 보내지 못한다.

앱별로 쓰는 장치:

- hwp: 실행 끝에 플러그인 `undo(바뀐 곳 수, 실행 시작 때 foreign)`로 되돌린다. 받아들이기는 새 플러그인 메서드 `redo(단계 수, 되돌린 뒤 foreign)`가 편집기의 `edit:redo`로 다시 넣는다. 미리보기는 기존 바뀐 곳 목록이다. 거부하거나 낡으면 다음 요청에 "사용자가 되돌렸다"는 기존 안내(`REVERTED_NOTE`)가 붙는다. 실행 중에 사람이 문서를 고쳐 foreign이 움직였으면 AI 것만 따로 뺄 수 없어 제안으로 붙잡지 않는다. 그때는 편집이 문서에 남고 카드가 그 사실과 기존 되돌리기 단추를 보인다.
- sheets: 실행이 적용한 `ChangePlan`을 순서대로 적어 두고, 실행 끝에 기존 [실행 취소]와 같은 길로 되돌린다(열린 파일은 Univer 실행 취소, 빈 통합 문서는 어댑터 이력). 미리보기는 기존 "제안된 변경" 카드(주소, 전 → 후, 서식·시트 이름·구조 변경)다. 받아들이기는 적어 둔 계획을 기존 적용 길(`autoApplySafePlan`)로 다시 넣는다. 낡음은 열린 파일에서 Univer 실행 취소 더미의 새 항목과 `planStillMatches`로, 빈 통합 문서에서 어댑터 리비전으로 본다. 뒤 계획이 거절되면 앞 계획을 되돌린다. 실행 취소에 남지 않는 큰 편집(10만 셀 넘음)이나 Univer 실행 취소 더미(20칸)를 넘는 실행은 되돌릴 수 없어 붙잡지 않고, 카드가 그 사실을 알린다. AI 도구 `merge_attached_workbooks`(첨부 통합 문서를 열린 문서에 들여오기)는 실행 취소 단계 없이 문서에 들어가므로 AI에게 내주지 않는다. 사람의 데이터 ▸ 통합 문서 병합은 그대로다.
- slides: 실행을 시작할 때 메인 프로세스가 덱과 실행 취소·다시 실행 더미를 기록한다(`src/main/ai-proposal.ts`). 실행이 끝나면 실행 뒤 상태를 떠 두고 덱과 두 더미를 실행 전 모양으로 되돌린다. 받아들이기는 실행 취소 한 단계를 쌓고 실행 뒤 상태를 넣으며, 실행 전 상태를 기존 AI 되돌리기 지점으로 등록한다. 낡음은 실행 취소 더미 맨 위·길이, 다시 실행 길이, 편집 순번으로 본다. 미리보기는 달라진 슬라이드(최대 4장)의 전·후 축소 그림이다. `generate_deck`의 교체 모드는 파일에서 연 덱이면 거절한다. 교체는 경로가 없는 새 세션을 만들어 스냅샷으로 되돌릴 수 없기 때문이다. 모델에게는 새 페이지를 덧붙이고 옛 페이지를 지우라고 답한다(그것은 제안으로 붙잡힌다). 경로가 없는 새 덱의 교체는 붙잡힌다.

| E. 고치는 도구를 앱째 꺼 두기                           | 가장 작다                                                  | 세 앱 모두 A로 검토할 수 있어 필요 없다. A로 붙잡지 못하는 도구 둘(sheets `merge_attached_workbooks`, 파일 덱의 slides `generate_deck` 교체)만 끈다                             |

## 결과

- 세 앱의 AI 편집은 실행이 끝나면 문서 밖의 제안이 되고, 사람이 받아들여야 문서에 들어간다. 각 앱에 가짜 모델로 진짜 `AgentLoop`와 앱의 스킬을 돌려 (가) 받아들이기 전 문서가 실행 전과 같고, (나) 받아들이면 실행이 만든 상태와 같고, (다) 거부하면 실행 전과 같고, (라) 되돌린 뒤 문서가 바뀌면 받아들이기가 거절되고 문서가 그대로인 것을 보는 시험이 있다(`apps/hwp/tests/ai-turn-proposal.test.ts`, `apps/sheets/tests/ai-turn-proposal.test.ts`, `apps/slides/tests/ai-proposal.test.ts`·`ai-panel-proposal.test.ts`). hwp는 진짜 rhwp 문서를 `exportHwp()` 바이트로, slides는 진짜 세션의 슬라이드와 압축 항목 바이트로, sheets는 빈 통합 문서 어댑터의 전체 상태로 견준다.
- 진짜 rhwp 편집기(웹에서 띄운 스튜디오)에서 플러그인으로 문단을 넣고 `undo`·`redo`를 부르면 내보낸 바이트가 실행 전·후와 같았다.
- 사람이 받아들이거나 거부해야 다음 AI 요청을 보낼 수 있다. "새 대화"나 다른 문서 열기는 제안을 버린다.
- 붙잡지 못하는 경우(위 hwp·sheets 항목)는 편집이 문서에 남는다. 규칙에서 벗어나는 길이라 카드가 그렇게 알리고 기존 되돌리기를 남긴다.
- 남은 위험: 실행이 도는 동안 저장하거나 자동 저장(복구 사본)이 돌면 진행 중인 AI 편집이 쓰인다. 실행 중 저장을 막는 일은 각 앱 저장 흐름을 건드려야 해서 이 단위에서 하지 않았다.
- 남은 위험: sheets와 slides는 실행 중 사람이 직접 고친 것도 실행과 함께 되돌려 제안에 들어간다(사람 편집과 AI 편집을 가르는 셈이 없다). hwp는 이 경우 붙잡지 않는다.
- 남은 위험: 거부 뒤 hwp와 sheets(열린 파일)에서 편집기의 다시 실행(Ctrl+Y)이 AI 편집을 되살릴 수 있다. 사람의 명령이라 막지 않았다. slides는 다시 실행 더미에 남기지 않는다.
- 남은 일: sheets와 slides는 거부를 모델에게 알리는 안내가 없다. 다음 요청의 문맥이 지금 문서를 다시 읽어 주지만, 대화 기록에는 적용했다는 도구 결과가 남는다. sheets 열린 파일 경로(Univer)는 시험 환경에 Univer가 없어 코드와 타입검사로만 확인했다. 세 앱 모두 Electron 화면에서 카드를 눈으로 확인하지 못했다(slides 카드는 jsdom 시험으로 본다).
- 범위 밖: 새 문서를 만드는 AI 경로(sheets `create_document`, slides 프로젝트 "만들기"로 넘어온 덱)는 열린 문서를 고치지 않아 그대로 둔다. 웹 빌드의 AI는 여전히 지원하지 않는다(웹 AI 단위).
