# 0003 1단계는 스위트 앱 웹 읽기 모드

- 날짜: 2026-11-08
- 상태: 확정
- 결정한 사람: 메인 세션 판단, 스풋 변경 가능(2026-11-08 d5에서 유효로 확정)

## 맥락
유유 메신저에서 첨부 문서를 보는 기능이 출발점이었다. 비교 시험(REPORT.md)은 형식별 보기 라이브러리(docx-preview, pdf.js, SheetJS 등)를 쟀다. 스풋 말: "어차피 seuoffice 만들면 다른 것들(별도 보기 라이브러리) 쓸 필요가 없다".

## 결정
1단계는 스위트 앱(이음 docs, sheets, slides, pdf, hwp) 자체를 브라우저에서 읽기 모드로 띄운다. 입력은 바이트와 파일 이름이고, 변환 서버 없이 정적 파일만 쓴다.

"읽기 모드"의 정의:
- 문서를 열어 보이고 넘겨 보고 확대할 수 있다.
- 저장 경로는 웹에 없다. 브리지가 `WebUnsupportedError`로 거절한다.
- docs는 읽기 모드로 시작하고 리본을 접는다. sheets는 `readOnly: true`로 연다.
- slides, hwp, pdf의 편집 조작은 메모리에서만 바뀌거나, 브리지 거절로 앱의 오류 표시가 난다. 페이지가 죽지는 않는다.

## 버린 대안
- 형식별 보기 라이브러리 조합: 편집 단계에서 다시 스위트 앱으로 갈아타야 하고, 화면이 형식마다 다르다. REPORT.md는 형식별 정확도 비교 참고로만 둔다.

## 결과
- 같은 화면이 2단계(웹 편집)로 이어진다.
- xlsx는 Rust 사이드카 엔진을 WASM으로 옮겨야 해서 1단계의 가장 큰 위험이다.
