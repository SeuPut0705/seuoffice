# 0011 웹 글꼴

- 날짜: 2026-11-09
- 상태: 확정
- 결정한 사람: U9 세션(메인 세션이 맡김). 스풋이 뒤집을 수 있다.

## 맥락

데스크톱은 디자인 템플릿 글꼴 10종(13개 파일, 약 51MiB, 모두 SIL OFL 1.1, `packages/ui/template-fonts`)을 설치 파일에 한 번 넣고, 자체 URL 스킴(`genoffice-docx-media://template-fonts/<파일>`)으로 렌더러에 준다. docs와 sheets는 시작할 때 면마다 URL로 `FontFace`를 등록만 하고, 글을 그릴 때 처음 쓰는 면만 읽는다. slides는 메인 프로세스의 글꼴 레지스트리가 파일을 읽어 줄 폭을 재고, 렌더러는 그 바이트로 면을 등록한다.

웹 빌드는 이 글꼴을 하나도 싣지 않았다. docs와 sheets는 등록 모듈을 빈 모듈로 바꿨고, slides는 Carlito와 덱 안 글꼴만 썼다. 그래서 이 글꼴을 지정한 문서가 웹에서 대체 글꼴로 그려졌다. 한글 문서 스튜디오는 옛한글 글꼴(`RHWPOldHangul-Regular.woff2`)을 시작할 때 받으려다 실패했다. 스튜디오 빌드가 rhwp의 글꼴 폴더를 통째로 뺐기 때문이다.

## 결정

1. 템플릿 글꼴은 웹 묶음에 한 번만 싣는다. `apps/web/scripts/build.mjs`가 `packages/ui/template-fonts`(글꼴, 라이선스, README)를 `dist/template-fonts/`로 복사한다. 앱마다 따로 복사하지 않는다.
2. 웹 빌드는 `@genoffice/ui/template-fonts`를 `packages/web-platform/src/template-fonts.ts`로 돌린다(`seuofficeWebAliases`). 표는 그대로 두고 `templateFontUrl`만 앱 페이지 기준 `../template-fonts/<파일>` 주소로 바꾼다. docs와 sheets는 데스크톱 등록 코드(`registerTemplateFonts`, 줄 높이 비율, 시트의 미리 불러오기와 다시 그리기)를 그대로 쓴다. URL `FontFace`는 쓰일 때만 받아 온다.
3. slides 웹 세션은 덱의 XML이 이름을 대는 템플릿 패밀리의 파일만 열기 전에 받아 메모리 파일 시스템에 넣고, 글꼴 레지스트리에 그 폴더를 알려 준다. 줄 폭 계산과 화면 그리기가 데스크톱과 같은 경로를 탄다.
4. 옛한글 글꼴은 스튜디오가 빌드된 rhwp 고정 커밋의 `assets/fonts/`에서 꺼내 `dist/hwp/studio/fonts/`에 라이선스와 함께 둔다. Adobe Source Han Serif K의 부분 집합을 rhwp가 예약 글꼴 이름을 피해 `RHWP Old Hangul`로 바꾼 파일이고 SIL OFL 1.1이다. rhwp의 근거 기록이 적은 SHA-256과 다르면 빌드가 멈춘다.

## 버린 대안

- 앱마다 글꼴 복사: 묶음이 앱 수만큼 커진다. 브라우저 캐시도 앱마다 따로 쌓인다.
- 웹용 등록 모듈을 앱마다 새로 작성: 데스크톱 등록 코드(줄 높이 비율, 시트 다시 그리기)를 두 벌로 관리하게 된다.
- 부분 집합 글꼴이나 woff2로 줄이기: 파일 이름과 메트릭을 그대로 두는 원칙(README)과 부딪힌다. PDF로 내보낼 때 글꼴이 들어가는 방식도 다시 확인해야 한다.
- `build-studio.mjs`(상위 파일)에서 옛한글 글꼴을 복사: 데스크톱도 고쳐지지만, 이 단계의 범위는 웹이다. 데스크톱에도 같은 빈틈이 있어 이음오피스에 알릴 일로 남긴다.

## 결과

- 웹 묶음(`apps/web/dist`)이 약 51MiB 커진다. 숫자는 U9 보고에 있다. 내려받는 양은 쓰는 패밀리만큼만 는다.
- `@seuoffice/web` npm 패키지(`files: dist`)도 그만큼 커진다.
- slides의 시스템·Office 글꼴(맑은 고딕 등)은 여전히 웹에 없다. 브라우저가 권한을 묻지 않고 PC 글꼴 파일을 읽을 방법이 없다.
