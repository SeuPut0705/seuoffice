# 0015 웹 암호 문서는 데스크톱 암호 모듈을 그대로 쓴다

- 날짜: 2026-11-09
- 상태: 확정
- 결정한 사람: U10 세션(메인 세션이 맡김). 스풋이 뒤집을 수 있다.

## 맥락

웹에서 암호 걸린 PDF와 docx를 열지 못했다. 데스크톱은 이 일을 main 프로세스에서 Node `crypto`로 한다.

- PDF: `apps/pdf/src/main/pdf-crypt.ts`(표준 보안 처리기 R2~R6, RC4·MD5·AES-128/256·SHA-2). 저장은 `save-pdf.ts`의 `applySaveRequest`가 원래 암호로 풀고, 고치고, 다시 잠근다.
- docx: `apps/docs/src/main/docx-encryption.ts`가 `officecrypto-tool`(ECMA-376 Standard·Agile)을 부른다. 같은 파일이 "디스크 암호"와 "다음 저장 암호"를 렌더러별로 들고 있다.

두 모듈 모두 Node의 동기 API(`createCipheriv`, `createDecipheriv`, `createHash`, `createHmac`, `getHashes`, `randomBytes`)를 부른다. 웹 `crypto` 대체 모듈에는 해시와 난수만 있었다.

## 결정

1. 두 모듈을 웹 빌드에 그대로 들인다. 복사본을 만들지 않는다. PDF는 `apps/pdf/vite.web.config.ts`의 데스크톱 전용 단계 목록에서 `pdf-crypt`를 뺀다. docs는 웹 브리지가 `docx-encryption.ts`와 `doc-format.ts`를 바로 import한다.
2. 웹 `crypto` 대체 모듈(`packages/web-platform/src/shims/impl/crypto.ts`)에 AES-128/192/256 CBC·ECB(`createCipheriv`, `createDecipheriv`, `setAutoPadding`, 블록 단위 `update`/`final`)와 `getHashes`를 더한다. 구현은 `@noble/ciphers`다. 이미 쓰는 `@noble/hashes`와 같은 저자·같은 방식(MIT, 동기)이다. 입력으로 숫자 배열도 받는다. Node 밖에서 `cfb`가 스트림 내용을 배열로 내주고, `officecrypto-tool`의 Standard 해독이 그 배열(소금값)을 그대로 해시하기 때문이다. Node의 `crypto`는 배열을 거절한다.
3. docs 웹 브리지는 데스크톱 암호 상태 함수(`rememberDocPassword`, `setDocPassword`, `snapshotDocPassword`, `commitDocPasswordSave`, 의도 번호)를 렌더러 번호 0 하나로 쓴다. 한 페이지에는 렌더러가 하나다.
4. `officecrypto-tool`이 끌어오는 `xml2js`는 `events`를 상속한다. 그래서 `events` 패키지(MIT, 브라우저용 EventEmitter)를 `@seuoffice/web-platform` 의존성으로 둔다. `timers`·`stream`은 쓰이지 않는 갈래(비동기 파싱, 스트림 파서)에서만 읽혀 브라우저 빈 모듈로 둔다.

## 버린 대안

- Web Crypto(`crypto.subtle`)로 AES: 비동기라 동기 API를 부르는 데스크톱 모듈을 고쳐야 한다. 평문 http에서는 `crypto.subtle`이 없다.
- 웹 전용 해독 코드를 새로 쓰기: 데스크톱과 결과가 갈릴 수 있고 상위 수정을 두 번 따라가야 한다.
- `crypto-js`(이미 `officecrypto-tool`이 씀)로 AES: WordArray 변환이 들고 느리다. 유지보수도 끝났다.

## 결과

- 웹에서 암호 PDF(RC4, AES-128, AES-256, 소유자 암호만 있는 파일)와 암호 docx(Agile, Standard)가 앱의 암호 묻기 창으로 열린다. 틀린 암호는 앱의 기존 오류를 보인다.
- 편집 모드 저장은 데스크톱처럼 같은 암호로 다시 잠근다. 앱의 암호 설정·해제(PDF "보호", docx "문서 보호")도 다음 저장부터 적용된다.
- docx 키 유도(Agile 100000회 SHA-512)는 순수 JS라 데스크톱보다 느리다. 열기와 저장마다 한 번씩 든다.
