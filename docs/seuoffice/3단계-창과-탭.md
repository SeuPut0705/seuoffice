# 3단계 W 묶음: 탭·분할·분리 창

- 날짜: 2026-11-13
- 근거: [3단계 셸 계약](3단계-셸-계약.md) 7절, 결정 [0029](decisions/0029-껍데기-선택.md), 2단계 단계 API(`TabCloseStep`, `resume_close`)
- 코드: `crates/shell-ipc/w/src/tabs/`, 비교: `tools/ipc-diff/groups/w/tabs*.ts`와 `tabs-lib/`, 결함: `tools/ipc-diff/faults/w-tabs.json`

`apps/shell/src/main/index.ts`의 `registerTabsIpc`, `registerSplitIpc`, `registerDroppedFilesIpc`와 `home:new-*`, 분리·떼어 내기·분할 도우미를 Rust로 옮겼다. 등록하는 채널은 `tabs/mod.rs`의 `register`에 있다.

## 자료의 모양

코어 스레드에 `TabsState` 하나가 산다(`Rc<RefCell<..>>`). `main-core`의 `TabManager<ViewId>`와 `DetachedWindows<ViewId, WindowId>`를 쥐고, `index.ts`가 모듈 변수로 갖던 것(`lastDockIndex`, `tornSplitDrag`, `lastSplitState`, 새 파일 폴더 기억)을 같이 가진다. 모든 처리기는 이 상태의 메서드다. 등록할 때 `Provided`에 `TabsState`를 더하므로 다른 W 모듈은 `provided.all::<TabsState>()`로 `open_document_path`, `route_document_path`, `with_manager`를 부른다.

`TabManager`는 호출 중에 `&mut self`를 쥐므로 호스트가 그것을 되읽을 수 없다. `index.ts`가 그 자리에서 `manager.list()`를 읽던 곳(`onChanged`, `dockHost.dock`, `handleSplitChanged`)은 `Bridge`가 `Effect`로 쌓았다가 호출이 끝난 뒤 순서대로 돌린다.

## 두 호스트

- `WindowsHost`(`Send + Sync`, `Hosts`에 넣는다): 창, 뷰, 화면, 타이머, 네이티브 메뉴. 메서드 하나가 Electron 호출 하나다. 기다리던 것(`Menu.popup`, `pageLoaded`, 타이머)은 `HostEvents`로 나중에 답한다. Tauri가 구현한다(`crates/shell/src/host/window.rs`).
- `TabHooks`(코어 스레드, `Provided`에 넣는다): 편집기 모듈 호출(`createDocsView`, 더러움 묻기, 시드 올리기), 셸의 글(`tm`), 메뉴(M), 열기 경로(최근, 드라이브). D1·D2·M이 상태를 코어 스레드에 두므로 `Send`가 아니다. 셸이 묶음을 등록하기 전에 하나를 더한다. 없으면 `RegisterError::MissingHost`로 시작하지 않는다.

## 셸이 해야 할 일

1. `Hosts`에 `WindowsHostRef`를 넣고 `Provided`에 `dyn TabHooks`를 더한다.
2. `WindowsHost::attach`로 받은 `HostEvents`에 창·뷰·타이머·메뉴 사건을 보낸다. 사건은 코어 스레드에서 `TabsState::host_event`로 간다.
3. 셸 창을 만들 때 `TabsState::shell_window_opened`, 닫힐 때 `shell_window_closed`를 부른다. 분리 창의 `close`는 늘 막고 `HostEvent::Window(.., Close)`로 알린다. 상태가 닫아도 되면 `window_destroy`를 부른다.

## 기다림

코어 스레드는 렌더러나 메뉴를 기다리지 않는다. 탭 닫기는 `TabCloseStep`을 `DocumentEditors::request_close`로 수행하고 나머지 흐름을 답의 연속에 둔다. 메뉴는 `popup_menu`가 바로 돌아오고, `HostEvent::Menu`가 오면 고른 항목을 실행한 뒤 invoke에 답한다.

## 비교(`ipc-diff`)

TypeScript 쪽은 진짜 `index.ts`를 불러 `second-instance` 듣는 함수로 진짜 셸 창과 `TabManager`를 만든다. Electron과 편집기 모듈은 `tabs-lib/world.ts`가 가짜로 바꾸고, 호출마다 한 줄씩 기록한다. Rust 쪽 가짜(`tabs/probe.rs`)는 같은 줄을 쓴다. 가짜 세계의 답은 케이스의 `hosts.w`에서 온다(`probe.rs` 머리말에 목록).

- 타이머는 기록만 하고 울리지 않는다.
- 탭 메뉴가 80자가 넘는 경로를 줄이므로 그룹은 `TMPDIR=/tmp`로 케이스 폴더를 짧게 한다.
- 열린 문서를 가리는 모듈 변수(`detached`, `torn`)는 케이스마다 `closeDetachedWithoutPrompt`로 비운다.

## 아직 이 묶음에 없는 것

- `ensureTabLoaded`, `hydrateSession`, `openDocuments`의 단계를 돌리는 쪽(세션 복원, MCP). `TabsState::with_manager`로 `TabManager`에 닿을 수 있고, 페이지 로드가 끝나면 `HostEvent::PageLoad`가 `ready_settled`를 부른다. 단계를 이어 주는 코드는 세션 복원을 맡은 쪽이 쓴다.
- `applyPendingDir`(저장된 파일 훅이 새 파일을 폴더로 옮기는 일). 상태는 `pending_dir_for`, `clear_pending_dir_for`로 내놓는다.
- 스킬 끌어 놓기(`drop_skill_file`, `drop_no_skills_found`)와 `home:open-agent-window`의 창 열기는 훅으로 A 묶음에 넘긴다. `ipc-diff`는 이 둘의 성공 경로를 덮지 않는다.
