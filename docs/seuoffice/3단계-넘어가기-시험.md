# 3단계 넘어가기 시험

- 날짜: 2026-11-13
- 근거: 결정 [0029](decisions/0029-껍데기-선택.md)의 "남은 받아들이기 시험", [3단계 셸 계약](3단계-셸-계약.md) 8절 "마지막 묶음"
- 맡은 곳: U 묶음(업데이트·설치). 계획과 스크립트는 이 문서와 `tools/migration-test/`, 러너 작업 흐름은 `.github/workflows/seuoffice-migration.yml`이다. 실기기 실행은 여섯 묶음이 끝난 뒤의 마지막 묶음이 한다.

Electron 판을 쓰는 사람이 앱 안 업데이트만으로 CEF 판에 이르고, 그동안 쌓은 자료를 그대로 쓰는지 본다. 0029는 이 시험을 통과해야 확정이고, 하나라도 실패하면 0029를 다시 연다.

## 1. 넘겨야 하는 자료

| AI 키                                    | `ai-settings.json`, `safeStorage`로 봉함     | 설정 → AI 모델에 저장됨으로 보임, AI 질문이 된다   | 예: `aiOffice.getAiSettings()` |

## 2. 판

- **오래된 판**: Windows 설치 파일(`SeuOffice-Setup-<판>.exe`)이 붙은 가장 오래된 안정 판. 작업 흐름은 `oldest`로 찾는다.
- **마지막 판**: CEF 판 바로 앞의 마지막 Electron 안정 판. 마지막 판은 CEF로 넘어가는 데 필요한 일(아래 4절의 localStorage 내보내기, 키체인 R1 가운데 고른 것)을 담고 나온다. 그래서 오래된 판은 마지막 판을 거치지 않고 CEF로 바로 가도 자료를 잃지 않아야 한다.
- **CEF 판과 그다음 판**: 같은 피드에서 CEF 판이 다시 업데이트되는지 보려고 판 번호만 다른 CEF 판 둘을 쓴다.

## 3. 길

| ----------------- | -------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 업데이트          | 오래된 판, 마지막 판 | 앱 안 업데이트 창에서 "지금 업데이트", "다시 시작하고 설치"                                 | 새 판이 뜨고, 1절의 자료가 모두 화면에서 그대로다                                                                                                                                    |

| 새 판이 뜨지 않음 | 오래된 판, 마지막 판 | 새 실행 파일이 시작하지 못하게 한다(Windows IFEO, 관리자 필요)                              | 옛 Electron 판이 돌아와 그 판 번호로 뜨고 자료가 그대로다                                                                                                                            |

macOS는 업데이트와 두 번째 업데이트만 러너에서 돈다. macOS의 바꿔 끼우기(`mac-update.ts`)는 새 앱의 서명을 확인한 뒤에야 옛 앱을 옮기므로, 실패를 일으키는 길은 실기기에서 손으로 한다(5절).

## 4. CEF 판이 지켜야 하는 것

스크립트는 Electron 판의 업데이터를 그대로 쓴다. CEF 판은 U 묶음의 호스트(`crates/shell/src/host/update.rs`, `tauri.conf.json`의 번들·NSIS 절)에서 다음을 지킨다.

1. **같은 피드.** 릴리스에 `latest.yml`·`stable.yml`(Windows), `latest-mac.yml`·`stable-mac.yml`(macOS)을 electron-updater 6 형식(`version`, `files[].url/sha512/size`, `path`)으로 붙인다. Electron 판이 그것으로 CEF 설치 파일과 zip을 받는다. CEF 판의 업데이터도 같은 파일을 읽고, 설치 폴더의 `resources/app-update.yml`(Windows), `Contents/Resources/app-update.yml`(macOS)에서 공급자와 채널을 읽는다. 시험은 이 파일을 `provider: generic`과 로컬 주소로 바꿔 쓴다.
2. **같은 설치 프로그램 인자.** NSIS 설치 파일은 electron-updater가 부르는 `--updated /S --force-run`을 받는다. 같은 폴더(`HKCU\Software\<키>\InstallLocation`)에 깔고, 앱 목록 항목은 하나로 남긴다. 0029 (a)에서 시제품이 증명한 방법이다.
3. **macOS 바꿔 끼우기.** CEF 판 zip은 `stageMacUpdate`의 확인(번들 ID `com.seuput.seuoffice`, 판 번호, `codesign --verify --deep --strict`)을 통과한다.
4. **되돌리기.** "새 판이 뜨지 않음"이 통과하려면 무언가가 옛 판을 돌려놓아야 한다. Electron의 NSIS는 옛 판을 먼저 지우므로 지금은 돌려놓는 것이 없다(Electron에서 Electron으로 가는 길이 기준을 잰다). CEF 설치 프로그램이 옛 설치 폴더를 옆에 옮겨 두고, 새 판이 처음 떠서 "시작함" 표시를 남기지 않으면 다음 실행 때 옛 폴더를 되돌린다. 설계는 U 묶음의 호스트 일이고, 이 시험이 그 설계를 받아들인다.
5. **설치 실패 알림.** 설치 도중 꺼진 뒤 옛 판이 뜨면 업데이트 창이 `install-failed`를 보인다(`update_attempt`, 지금 Electron과 같다).
6. **localStorage 들이기.** CEF 프로필은 `{캐시}/com.seuput.seuoffice/cef`에 따로 생긴다(0029 결과). CEF 판이 처음 뜰 때 Electron 프로필의 `Local Storage`(LevelDB)를 읽어 들인다. 마지막 Electron 판이 따로 내보낼지는 들이기가 오래된 판의 LevelDB를 읽을 수 있는지로 정한다.
7. **AI 키.** Windows는 DPAPI로 연다(0029 (b), A 묶음의 `host/secrets.rs`). macOS는 키체인 대화상자를 한 번 보이거나(지금 업데이트와 같은 수준), R1(마지막 Electron 판이 새 껍데기를 `-T`로 올려 다시 봉함)이나 서명 정체 고정으로 없앤다. macOS 러너의 AI 키 확인은 대화상자를 누를 사람이 없어 R1이나 서명 고정 없이는 실패한다. 그 실패가 어느 길을 고를지 정하는 근거다.
8. **시험용 디버깅 포트.** CEF 판은 `--remote-debugging-port=<포트>`를 받아 CEF에 넘긴다. 스크립트가 넘어간 앱의 화면을 그 포트로 읽는다. 브리지는 Electron과 같은 전역(`window.aiOffice`, `window.aiOfficeUpdate`)을 만든다(계약 4절).

## 5. 실행

### 러너

```sh
# 하네스 자체 시험과 기준: Electron 판에서 Electron 판으로
gh workflow run "seuoffice migration" --ref <가지>
# CEF 판: 설치 파일과 zip을 아티팩트로 낸 실행 번호
gh workflow run "seuoffice migration" --ref <가지> -f to_run=<CEF 빌드 실행> -f next_run=<다음 판 빌드 실행>
```

- Windows: 시작 판(`oldest`, `previous`) × 길(정상, 설치 도중 끄기, 새 판이 뜨지 않음, 잠긴 파일). 결과는 아티팩트 `migration-windows-<판>-<길>`의 `result.json`, `seed.json`, userData 해시, 피드 기록이다.
- macOS: 시작 판 × 정상. 아티팩트 `migration-mac-<판>`.
- CEF 판 없이 돌리면 시작 판에서 두 번째 최신 안정 판으로 가고, 이어 최신 안정 판으로 다시 간다.

### Windows 데스크톱

```powershell
gh auth login
.\tools\migration-test\win-desktop.ps1 -From v0.12.29 -To C:\b\SeuOffice-Setup-0.13.0.exe -ToVersion 0.13.0 `
  -Next C:\b\SeuOffice-Setup-0.13.1.exe -NextVersion 0.13.1 -Out C:\mig\oldest-none
```

- SeuOffice가 이미 깔린 PC에서는 `-Force` 없이는 멈춘다. 그 PC의 `%APPDATA%\seuoffice`를 쓰고 바꾸기 때문이다. 시험 전용 사용자 계정에서 돌린다.
- `-Fault kill-installer`, `-Fault lock-file`, `-Fault block-start`(관리자 PowerShell)로 실패 길을 돈다.
- 스크립트가 보지 않는 자료(프로젝트 대화, 복구본, 설정 화면)는 같은 실행 사이에 사람이 확인한다. 시드 단계 뒤 스크립트가 앱을 닫기 전에 멈추게 하려면 `seed` 다음 줄에서 끊고 손으로 만든 뒤 다시 잇는다.

### Mac 실기기(손으로)

1. 시험 전용 macOS 사용자에서 오래된 판 zip을 `/Applications`에 풀고 연다.
2. 1절의 자료를 만든다. 설정 두세 가지, 문서 셋 열기(최근 목록), 프로젝트 하나에 대화 둘, AI 키, 문서를 고치고 30초 기다린 뒤 강제 종료(복구본).
3. `node tools/migration-test/feed.mjs make --file <CEF zip> --version <판> --out <폴더>`, `serve`, `point --resources /Applications/SeuOffice.app/Contents/Resources --url http://127.0.0.1:8765/`, `codesign --force --deep -s - /Applications/SeuOffice.app`.
4. 앱을 다시 열고 업데이트 창에서 업데이트한다. 키체인 대화상자가 뜨면 몇 번 떴는지 적는다.
5. 1절의 자료를 화면에서 하나씩 확인한다. 실행 복구 목록에 2단계의 복구본이 뜨는지 본다.
6. 실패 길: 바꿔 끼우기 스크립트(`mac-update.ts`의 `startMacSwap`이 띄운 셸)를 끝내거나, 새 앱의 실행 파일 실행 권한을 지운 zip을 피드에 올려 옛 판이 남는지 본다.
7. 마지막 판으로 1~6을 다시 한다.

### 0029의 "재지 않은 것"

IME(한글 조합), 복사·붙여넣기, 큰 시트, 슬라이드 그리기, PDF 보기, 공동 편집은 넘어간 CEF 판에서 사람이 돌린다. 이 스크립트의 범위가 아니다.

## 6. Electron 기준에서 본 것

2026-11-13 러너 실행 [43413384766](https://github.com/SeuPut0705/seuoffice/actions/runs/43413384766)(시작 판 v0.12.12, v0.12.39, 업데이트 대상 v0.12.40). 스크립트 결함 두 가지(판 번호 `x.y.z.0`, IFEO를 옛 앱이 뜨기 전에 건 것)는 그 뒤 고쳤고, 고친 판의 실행은 2026-11-14 러너 정지로 아직 돌지 않았다.

- **Windows 업데이트.** 두 시작 판 모두 설치, 자료 만들기(localStorage, AI 키, 최근 목록), 앱 안 업데이트 창으로 0.12.40 설치까지 됐다. 넘어간 앱의 자료 확인은 판 번호 비교 결함 때문에 돌지 못했다.
- **Windows 설치 도중 끄기.** 두 시작 판 모두, 설치 프로그램을 시작 5초 뒤에 끄자 설치 폴더에 `SeuOffice.exe`가 남지 않았다. Electron 판에는 되돌리기가 없다는 것을 기준이 확인했다. CEF 설치 프로그램은 4절 4항을 새로 갖춰야 한다.
- **macOS 업데이트.** 두 시작 판 모두 설치, 자료 만들기, 앱 안 업데이트(내려받기, 풀기, 서명 확인, 바꿔 끼우기)까지 됐고 번들이 0.12.40이 됐다. 넘어간 앱을 디버깅 포트로 읽는 단계가 실패했다. 원인은 아직 모른다. 다음 실행이 그때의 프로세스, 포트, `update-log.txt`를 남긴다.

## 7. 끝나는 조건

- 3절의 모든 길이 두 OS에서 통과한다(macOS 실패 길은 손으로).
- 실패한 길이 하나라도 있으면 0029를 다시 연다. 실패가 Electron에서 Electron으로 가는 기준 실행에서도 똑같이 나면 그 길은 CEF가 새로 만든 결함이 아니다. 그래도 4절의 되돌리기처럼 CEF 판이 새로 약속한 것이면 통과해야 한다.
- 통과하면 Electron과 공용 진입 모듈, `main-node`를 지운다(계약 8절).
