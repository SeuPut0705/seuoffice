## 1단계: 웹 읽기 모드

- 다섯 형식(PDF, docx, xlsx, pptx, hwp/hwpx)을 스위트 앱 그대로 브라우저에서 읽기 모드로 연다.
- 부품: `@seuoffice/embed`와 `apps/web` 정적 묶음.
- 한글 같은 형식 왕복 측정.
- 완료 조건: 웹 시험 통과, web-gaps 기록.
- 위험: xlsx 엔진 WASM 이식. 결과: `wasm32-wasip1` reactor로 컴파일과 실행 모두 됐다(엔진 편집은 `target_os = "wasi"` 분기 2곳).
- 상태: 완료(2026-11-08). 웹 시험 8건 통과. `web-gaps.md`에 남은 차이 52건(pdf 10, hwp 9, docs 9, slides 15, sheets 9). 그중 2단계에 먼저 볼 것: sheets 읽기 모드 미적용(렌더러가 `readOnly`를 읽지 않음), 웹 글꼴 묶음(docs·sheets 템플릿 글꼴, hwp PC 글꼴, slides 시스템 글꼴). 한글 왕복 측정은 `hwp-왕복-측정.md`(저장소 37개, 불일치 0).

## 1.5단계: 공개와 판 내기

- 저장소 전체를 Apache-2.0으로 공개한다(결정 0007). open-core로 나누지 않는다.
- 공개 전 검사: NOTICE 출처 정리, 이력의 비밀값과 내부 정보 검사, `ee/` 반입 막는 검사 확인. 공개 전환은 스풋 확인 뒤에 한다.
- 판 내기: `@seuoffice/*`를 판 번호를 붙여 npm에 낸다. 유유는 판을 고정해 받고, 판 올리기 커밋과 배포 전 검사를 거쳐 운영에 넣는다.
- PC 프로그램은 유유용 안정 판 채널을 따로 둔다(4단계에서 만든다).
- 상태: 진행 중. 공개 전 검사를 마치고 2026-11-08에 공개로 바꿨다. 이력에서 로컬 경로와 개인 메일을 지우려고 우리 커밋 29개를 고쳐 썼다(이음 `aea1414`까지는 그대로). gitleaks로 이력을 검사해 15건이 나왔는데 모두 상위 시험용 가짜 키였다. `@seuoffice/embed`(13kB)와 `@seuoffice/web`(41MB, 정적 묶음)은 `npm publish --dry-run`이 통과하고, `v*` 태그를 밀면 신뢰 게시(OIDC)로 내는 워크플로가 있다(`판-내기.md`). 실제 게시는 스풋이 npmjs.com에 `seuoffice` 조직을 만들고 첫 판을 낸 뒤 신뢰 게시자를 등록하면 된다.

## 2단계: 웹 편집과 저장

- 앱별 저장 브리지: docx 생성·패치를 브라우저에서, xlsx `save_archive` wasm, pptx 저장 바이트, hwp `exportHwp*` + `applySaveFixes`를 브라우저에서, pdf는 pdf-lib 단계 먼저(pdfium wasm 단계는 나중에).
- embed 저장 메시지: `{type:'save', fileName, bytes}` → 호스트가 받아 저장하고 응답한다.
- 단일 편집자 잠금: 호스트(유유)가 잠금을 잡은 경우에만 `mode=edit`로 연다. 잠금을 못 얻으면 읽기 모드. 동시 편집은 하지 않는다.
- 암호 문서(pdf RC4·MD5 JS 구현, docx officecrypto 브라우저 확인).
- 완료 조건: 한글 왕복 측정에서 알려진 손실 외 불일치 0, 한컴 한글 수동 재열기 확인.
- 상태: 진행 중.
  - embed 편집·저장 계약(U0): `mode: 'edit'`, `onSave`, `onDirtyChange`, `save()`. 호스트는 한 문서의 저장을 도착 순서대로 하나씩 처리한다.
  - 한글(U4): 편집 모드에서 hwp/hwpx를 같은 형식으로 저장해 호스트에 넘긴다. 앱 저장(Ctrl+S, 파일 메뉴)과 호스트 요청 저장 모두 데스크톱과 같은 보정(`applySaveFixes`)을 거친다. 왕복 측정이 웹 경로도 함께 확인한다(37개, 불일치 0). 웹 시험 `save-hwp.spec.ts` 3건.
  - PDF(U8): pdf-lib으로 쓰는 편집(주석, 양식, 페이지 회전·삭제·순서, 메타데이터, 책갈피, 첨부)을 편집 모드에서 호스트로 저장한다. 텍스트·이미지 편집, 저장된 주석 삭제, 영구 제거, 암호는 웹에서 저장을 거절한다(결정 0010). 보기 모드는 읽기 전용이다. 웹 시험 `save-pdf.spec.ts` 4건.
  - 워드(U5): 편집 모드에서 앱 저장(버튼, Ctrl+S)과 호스트 저장 요청이 docx 바이트를 `saveToHost`로 넘긴다. 바이트는 원래 렌더러가 `@genoffice/docx-engine`으로 만들고, 메인 프로세스는 지연 그림 채우기·암호화·디스크 쓰기만 해서 엔진을 옮길 필요가 없었다. 보기 모드는 읽기 모드를 끌 수 없게 잠갔다(전에는 Esc로 편집이 됐다). 웹 시험 `save-docs.spec.ts` 5건.
  - 웹 글꼴(U9): 디자인 템플릿 글꼴을 웹 묶음 `template-fonts/`에 한 번 싣고 docs·sheets는 데스크톱 등록 코드를 그대로 쓴다. slides는 덱이 이름을 대는 패밀리만 받는다. hwp 스튜디오에 옛한글 글꼴을 넣었다(결정 0011, 웹 묶음 +51.4MiB). hwp PC 글꼴 목록과 slides 시스템 글꼴은 남는다. 웹 시험 `fonts.spec.ts` 5건.
  - 파워포인트(U6): 편집 모드에서 글 고치기, 슬라이드 추가·삭제, 노트, 되돌리기·다시하기가 페이지 안 세션에서 데스크톱과 같은 트랜잭션 코드로 돈다. 저장(Ctrl/Cmd+S, 저장 단추, 호스트 `save()`)은 `savePptx` 바이트를 호스트에 넘긴다. 나머지 편집 연산은 `web-gaps.md`에 남겼다. 웹 시험 `save-slides.spec.ts` 5건.
  - 남은 것: xlsx와 sheets 읽기 모드(U7), 암호 문서(U10), 한컴 한글 재열기(사람 몫).

## 3단계: AI 게이트웨이와 변경 추적

- `packages/ai-provider`에 `gateway-complete` 프로토콜을 추가한다(`AiProtocol`, `AI_PROVIDER_ADAPTERS`, `chat.ts`·`stream.ts` 분기, `protocols/gateway-complete.ts`). 요청마다 부른 사람 토큰을 메모리로만 넘기고 설정 파일에 저장하지 않는다. 웹에서는 호스트가 게이트웨이를 부르게 한다.
- AI 편집 추적 강제: docs `ai/tools.ts`에서 `accept_changes`·`reject_changes`를 빼고, `ai/ops.ts`에서 AI 편집 추적을 항상 켠다.
- hwp·sheets·slides는 앱별 조사 뒤 "제안 → 미리보기 → 사람 수락"으로 한다.
- 상태: 진행 중. 게이트웨이와 docs AI 편집 추적 강제는 끝냈다(결정 0009). `gateway-complete`는 OpenAI Chat Completions 요청과 SSE 모양을 그대로 쓰고, 토큰은 요청마다 공급자(`setGatewayTokenProvider`)에게 받아 머리글에만 싣는다. docs에서 AI 편집은 사용자 토글과 상관없이 `AI Assistant` 작성자의 변경 추적으로 남고, AI는 변경을 받아들이거나 거절할 수 없다. 남은 것: 웹 embed AI 메시지, docs MCP 다리(`mcp-bridge.ts`)와 CLI `docs apply`의 추적, hwp·sheets·slides.

## 4단계: 앱 배포(Apple Silicon Mac, Windows)

- 앱 릴리스는 Apple Silicon Mac(arm64)과 Windows(x64) 두 가지만 낸다(스풋 결정, 2026-11-09). Linux와 Intel Mac은 빌드하지 않는다.
- `productName`·`appId`·창 제목 seuoffice(`apps/shell/package.json`, `electron-builder.cjs` :532–533, `packages/i18n` 제품명).
- 업데이트 피드: 저장소를 공개하면 GitHub 릴리스 피드를 쓸 수 있다. 유유용 안정 판 채널을 일반 채널과 따로 둔다(결정 0007).
- 코드 서명: 첫 배포부터 서명본으로 낸다. 미서명 뒤 서명본은 자동 업데이트가 안 된다(`docs/releasing.ko.md:110–111`). Windows는 인증서 방식을 스풋이 결정한다. Mac은 Developer ID 서명과 공증이 필요하다(Apple Developer Program 가입).
- 상태: 진행 중. 사용자에게 보이는 이름이 seuoffice(appId `com.seuput.seuoffice`)이고, 업데이트 피드는 `SeuPut0705/seuoffice` GitHub 릴리스다. 채널은 `latest`·`stable` 두 가지로 빌드할 때 정한다(`SEUOFFICE_UPDATE_CHANNEL`). `apps/shell/electron-builder.seuoffice.cjs`가 대상을 Mac arm64(dmg, zip)와 Windows x64(NSIS)로 묶고 다른 대상은 거부한다. `.github/workflows/seuoffice-desktop.yml`이 `v<판 번호>` 태그에서 두 플랫폼을 빌드하고, 둘 다 서명됐을 때만 릴리스를 만든다(결정 0013). npm 묶음 태그는 `npm-v<판 번호>`로 옮겼다. 남은 것: Apple Developer 가입·Developer ID 인증서·공증 자격, Windows 서명 인증서, GitHub 비밀값 등록(스풋 몫), 첫 서명 릴리스.

## 5단계: 동시 편집

- 동시 편집을 설계한다. 공개 여부는 1.5단계에서 정했다(결정 0007).
- 상태: 완료(2026-11-09). 결정 0008: 실시간 공동 편집은 하지 않고, 붙이는 쪽이 잠금·판 검사·넘겨주기를 맡는다. seuoffice 쪽은 2단계 저장 계약으로 충분하다. 실시간 편집은 결정에 적은 조건이 생기면 다시 연다.
