# ODS 열기와 내보내기 계획

상태: **1단계 구현됨, 사람 확인 남음**(2026-11-10). 2단계(내보내기)는 아직이다. 저장소 주인이 범위와 순서를 정했고, 정한 것과 그 이유는 결정 기록 [0119](../tracking/decisions/0119-ods-open-and-export.md)에 있다.

## 1. 무엇을 하려나

지금 이음오피스는 ODT(텍스트 문서)를 열고 고치고 저장하지만, ODS(스프레드시트)는 앱에서 열지 못한다. 파일을 열려고 하면 "지원되지 않습니다"가 나오고, 엑셀의 파일 고르기 목록에도 없다. 터미널 명령어의 `convert`만 `.ods`를 `.xlsx`로 바꾼다.

목표는 두 단계다.

1. **불러오기**: `.ods`를 골라 열면 값·날짜·수식·병합·크기를 옮긴 `.xlsx` 사본 세션으로 연다. 저장은 `.xlsx`로 하고, 원본 `.ods`는 건드리지 않는다.
2. **내보내기**: "ODS로 저장"을 더한다. 원본 바이트를 보존하는 편집이 아니라 **전체 변환**이고, 빠지는 기능을 미리 알린다.

원본 `.ods`를 고쳐 그대로 되돌려 쓰는 왕복 보존은 하지 않는다. 필요해지면 그때 별도 결정으로 다룬다.

`.ods`는 **기본 프로그램으로 잡지 않는다**. `.odt`처럼 "연결 프로그램"으로만 등록한다.

AI 채팅 첨부와 "시트 합치기" 원본에는 넣지 않는다. 첨부 읽기는 ODS를 읽는 코드가 따로 필요하고, 합치기는 조용한 변환이 하나 더 생긴다.

- Windows: `apps/shell/build/installer.nsh`에 `IeumOffice.OpenDocumentSpreadsheet` ProgId와 `.ods\OpenWithProgids` 값. 기본값(`APP_ASSOCIATE`)은 쓰지 않는다.
- Mac·Linux: MIME `application/vnd.oasis.opendocument.spreadsheet`를 `Alternate`로만 둔다.

`apps/shell/tests/file-associations.test.ts`가 `LAUNCHABLE_EXTS`와 설치 프로그램 목록이 같은지 본다. 목록을 더하면 이 시험도 함께 고친다.

### 엔진이 이미 하는 일

`apps/sheets/native/xlsx-engine/src/convert.rs`는 `calamine::open_workbook_auto`로 파일을 읽고 최소 `.xlsx`를 쓴다. calamine 0.37은 `.ods`를 읽는다(`Sheets::Ods`). 2026-11-09에 만든 견본 ODS로 확인한 것:

- 시트 이름, 문자열, 숫자, 날짜가 넘어온다. ODS의 ISO 날짜는 이미 엑셀 일련번호로 바꾼다.
- **수식은 ODF 문법 그대로 들어간다.** `=SUM(B1:B2)`가 `<f>of:=SUM([.B1:.B2])</f>`로 나와 엑셀과 이음오피스가 계산하지 못한다.
- 병합, 글꼴·채우기·테두리·숫자 서식, 열 너비·행 높이, 차트, 그림, 조건부 서식은 옮기지 않는다.

### 명령줄

`packages/cli/src/commands/convert.ts`의 `NODE_ROUTES`에 `ods: ['xlsx']`가 있다. `ieumoffice info`도 `.ods`를 읽는다. 이 길은 그대로 두고, 앱이 같은 변환기를 쓰게 한다.

## 3. 1단계 — 불러오기

### 3.1 여는 길

- 여는 창, 끌어다 놓기, 최근 목록, 폴더 목록, 홈, MCP에 `.ods`를 더한다(2절의 표). AI 첨부와 합치기 원본에는 넣지 않는다.
- `.ods`를 열면 `.xls`와 같은 길로 간다: 임시 폴더에 `.xlsx`를 만들고, 그 사본을 세션으로 연다. 세션은 원래 경로를 기억해 "다른 이름으로 저장"의 기본 이름을 원래 폴더의 같은 이름 `.xlsx`로 제안한다.
- 원본 `.ods`는 읽기만 한다. 복구 사본과 자동 저장은 사본 세션의 `.xlsx`를 따른다.
- 상태 표시줄에 한 줄을 계속 보여 준다: "ODS를 xlsx 사본으로 열었습니다. 저장하면 xlsx로 저장됩니다." 수식 손실이 있으면 같은 줄에 개수를 붙인다. 명령 결과를 잠깐 보여 주는 기존 상태 메시지와 별개의 값으로 두고, 창은 띄우지 않는다.

### 3.2 수식 번역

변환기(Rust) 안에서 ODF 수식 문법을 엑셀 문법으로 바꾼다. 새 파일 `apps/sheets/native/xlsx-engine/src/odf_formula.rs`에 모은다.

- `of:=` 접두사를 뗀다.
- 참조: `[.B1]` → `B1`, `[.B1:.B2]` → `B1:B2`, `[Sheet1.B1]` → `Sheet1!B1`, `[$Sheet1.$B$1]` → `Sheet1!$B$1`. 시트 이름에 공백이나 특수 문자가 있으면 작은따옴표로 감싼다.
- 인수 구분 `;` → `,`, 문자열은 그대로, `TRUE()`·`FALSE()`는 그대로.
- 함수 이름은 ODF와 엑셀이 같은 것을 그대로 둔다. `COM.MICROSOFT.` 접두사가 붙은 함수는 접두사만 뗀다.
- 범위 밖 문법(배열 상수, 교차·합집합 연산자, ODF 전용 함수)을 만나면 **그 셀의 수식만 버리고 값은 남긴다.** 파일 단위로 "수식 N개를 옮기지 못했습니다"를 알린다. 파일 열기를 거절하지 않는다.

시험은 시험 안에서 만드는 최소 ODS 꾸러미로 한다(값·날짜·시간·수식·병합·크기·번역 실패). 실제 ODS 프로그램이 만든 파일은 사람 확인에 쓴다. 수식 결과 값도 함께 적어 두어, 번역한 수식이 같은 값을 내는지 본다.

알려진 한계: `COM.MICROSOFT.IFS`처럼 엑셀 2007 이후에 들어온 함수는 접두사만 떼면 엑셀이 `#NAME?`으로 읽는다. 지금 번역기는 이 경우를 따로 가리지 못한다. 시간대가 붙은 ISO 날짜(`2026-03-05T10:20:30Z`)는 글자로 남는다.

### 3.3 1단계에서 옮기는 것과 미루는 것

옮긴다:

- 시트 이름과 순서, 문자열, 숫자, 불리언, 오류, 날짜·시간.
- 수식(3.2의 번역이 되는 것만), 수식 결과 값.
- 병합(`table:number-columns-spanned`·`table:number-rows-spanned`를 content.xml에서 읽는다 — calamine은 병합을 알려 주지 않는다).
- 열 너비, 행 높이(손으로 정한 것과 기본값).

미루거나 버린다(1단계에서는 알리기만 한다):

- 글꼴·글자색·채우기·테두리·맞춤, 숫자 서식(날짜 서식은 기본값으로 대신한다).
- 차트, 그림, 조건부 서식, 데이터 유효성 검사, 피벗, 틀 고정, 인쇄 설정, 메모.
- 암호가 걸린 ODS, 매크로.

서식까지 옮기는 일은 불러오기 방향의 다음 묶음으로 잡는다. 값과 계산이 맞는 것이 먼저다.

## 4. 2단계 — 내보내기

"ODS로 내보내기"를 더한다. 지금 탭은 xlsx로 그대로 두고, ODS 파일을 **사본으로** 새로 쓴다. 원본 바이트 보존이 아니고, 원본 `.ods`를 덮어쓰지 않는다. 내보낼 때 편집 중인 내용이 있으면 먼저 저장한 상태를 쓴다.

### 4.1 쓰는 곳

`apps/sheets/native/xlsx-engine`에 `convert_to_ods` 명령을 더한다. 읽기(`calamine`)와 달리 쓰기는 직접 만든다.

ODS 꾸러미는 다음을 갖춘다.

- `mimetype`(압축하지 않고 첫 항목), `META-INF/manifest.xml`, `content.xml`, `styles.xml`, `meta.xml`.
- `office:document-content`의 `office:body/office:spreadsheet`에 시트·행·셀.
- 값 종류: 문자열, float, boolean, date(`office:date-value`), 오류.
- 수식은 3.2의 역방향 번역으로 `table:formula="of:=…"`에 넣는다. 번역이 안 되는 수식은 값만 쓴다.

### 4.2 옮기는 것

- 시트 이름·순서, 값, 수식, 날짜, 병합, 열 너비, 행 높이.
- 글꼴·글자색·채우기·테두리·맞춤, 숫자 서식(엑셀 서식 코드를 ODF 데이터 스타일로 바꾼다).
- 틀 고정, 인쇄 설정(맞추기·방향·용지·여백·머리글·꼬리말).

### 4.3 버리는 것과 막는 것

- 차트, 그림, 조건부 서식, 데이터 유효성 검사, 피벗 테이블, 슬라이서, 메모, 매크로.
- 저장하기 전에 "이 문서에서 다음 기능은 ODS에 담지 못합니다: …"를 보여 준다. 항목은 실제로 그 문서에 있을 때만 적는다. 21개 언어.
- **원본 ODS 경로는 내보내기 대상으로 고를 수 없다.** 고르면 거절하고 다른 이름을 안내한다.
- **암호가 걸린 워크북은 ODS로 내보내지 않는다.** 암호를 푼 뒤에만 내보낸다. 암호 없는 파일이 조용히 만들어지지 않는다.

## 5. 하지 않는 것

- **원본 ODS 바이트 보존 왕복.** ODT는 결정 [0034](../tracking/decisions/0034-odt-through-word-editor.md)에서 docx 다리와 원본 조각 보존으로 풀었지만, ODS에 같은 방식을 쓰려면 쓰기 엔진 위에 조각 보존과 검증 도구가 더 필요하다. 1·2단계가 몇 달 밀린다.
- **`.ods` 기본 프로그램 등록.** 내보내기가 손실 변환이라, 기본으로 잡으면 사용자가 원본이 그대로 저장된 줄 안다. `.odt`와 같이 "연결 프로그램"으로만 둔다.
- **ODS를 AI 채팅 첨부로 읽기.** 지금 첨부 읽기는 xlsx만 읽는다. ODS 글 읽기를 따로 만들어야 해서 다음 묶음으로 미룬다.
- **ODS를 "시트 합치기" 원본으로 쓰기.** 조용한 변환이 하나 더 생긴다. 합치려면 xlsx로 저장한 뒤 쓴다.
- **암호 ODS, 매크로 ODS, 데이터베이스 범위.**

## 6. 순서

1. 이 계획과 결정 0119을 남긴다. (이 문서)
2. 1단계를 구현한다(구현됨): 여는 길, 변환 세션, 수식 번역, 병합·크기, 안내 문구, 시험.
3. 1단계를 내보내고 사용자 반응을 본다. ODS를 다시 저장하고 싶다는 요청이 실제로 쌓이는지 확인한다.
4. 2단계 범위를 표로 확정한 뒤 쓰기 엔진과 경고 창을 만든다.
5. 왕복 보존은 그 뒤에 별도 결정으로 검토한다.

## 7. 정한 것

- **번역이 안 되는 수식**: 값만 남기고 파일 단위로 개수를 알린다. 파일 열기를 거절하지 않는다.
- **1단계에 서식을 넣을지**: 값·계산·병합·크기만 먼저. 서식은 다음 묶음.
- **2단계 내보내기 방식**: 사본으로 내보낸다(탭은 xlsx로 남는다).
- **원본 덮어쓰기**: 원본 ODS 경로는 내보내기 대상으로 고를 수 없다.
- **암호 워크북**: ODS로 내보내지 않는다.
- **AI 첨부**: 1단계에서 뺀다.
- **합치기 원본**: ODS를 넣지 않는다.

## 8. 시험과 확인

- Rust: `convert.rs`의 ODS 견본 시험(값·날짜·수식 번역·번역 실패·병합·크기), `odf_formula.rs` 단위 시험.
- TypeScript: 파일 목록(`file-associations`, `open-with-icons`, `launch-paths`), 엑셀 여는 길(`WORKBOOK_EXTS`·고르기 목록), MCP `editorOpen`, 합치기 원본 목록에 ODS가 없는지.
- 앱에서 직접: ODS를 열어 값·수식이 맞는지, 저장이 `.xlsx`로 제안되는지, 원본 `.ods`가 바뀌지 않는지. 2단계에서는 저장한 ODS를 ODS를 읽는 다른 프로그램에서 열어 값·수식을 확인한다.
- 사람이 확인할 것: 21개 언어 문구, `.ods` 연결 프로그램 등록이 기본 프로그램을 바꾸지 않는지.
